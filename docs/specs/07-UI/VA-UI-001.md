# 화면 설계

## 0. 이 문서가 다루는 것

웹에 **어떤 화면이 있고, 어디서 어디로 가는지**, 그리고 **어느 화면에서든 같아야 하는 값**(디자인 토큰·공통 틀)을 정한다. 화면마다 요소가 어디에 어떻게 놓이는지는 다음에 쓰는 와이어프레임 문서가 정한다.

| 이 문서가 정하는 것 | 와이어프레임 문서가 정하는 것 |
|---|---|
| 화면 9개와 각 화면의 종류·목적·주 유스케이스 | 화면마다 요소 배치와 요소 번호 |
| 화면 사이의 이동(진입·이탈·주소) | 요소 하나하나의 규칙과 문구 |
| 색·글꼴·간격·모서리·움직임 토큰 | 화면별 시나리오 |
| 헤더·버튼·칩·다이얼로그 같은 공통 틀 | |

**모양의 원본은 승인된 디자인 캔버스다.** 2026-09-17에 사용자가 승인했다 — https://claude.ai/artifact/5vRnv2qFrhTBDjYaNZC1XR (보드 13개). **토큰 값의 원본은 이 문서다.** 프런트엔드 `styles.css`는 3장을 그대로 옮겨 적은 것이고, 컴포넌트에 값을 직접 쓰지 않는다(명세 작성 규약 1.9). 디자인을 바꾸면 이 문서를 먼저 고치고, 코드는 그 뒤에 따라간다.

**두 번째 캔버스 — 결과 그림과 파일 올리기.** 사용자가 첫 배포를 써 본 뒤 더한 것(한눈에 보기 · 대표 장면 · 인포그래픽 · 로컬 파일 끌어 놓기, [[VA-PRD-001#R11]] ~ [[VA-PRD-001#R13]] · [[VA-PRD-001#R1]])은 https://claude.ai/artifact/Y7ax1e9CfUWZyqVVrCa7tc (「Video Agent 결과 그림」, 보드 15개)가 모양의 원본이다. 사용자가 2026-09-29에 ①②줄을 「좋다」로, 2026-09-30에 ③줄을 「다음」으로 승인했다. 두 캔버스가 겹치는 곳(UI-1 · UI-3 · UI-4 · UI-5 · UI-7)은 두 번째가 이긴다 — 첫 캔버스에서 바뀌지 않은 부분은 그대로다. 이 문서에서 보드 이름 앞의 「그림 ·」은 두 번째 캔버스의 보드다.

**세 번째 캔버스 — 접근성 보강.** 키보드 초점 고리 · hover · 대비 미달 짝 · 한눈에 보기 키보드는 https://claude.ai/artifact/HQyWTuusSvs3yktqEHaQ4p (「VA 접근성 보강」, 보드 4개)가 모양의 원본이다. 사용자가 2026-10-01에 「다음」으로 승인했다. 화면을 새로 그린 캔버스가 아니라 **상태 보드**다 — 앞 두 캔버스의 화면에 초점 · hover 모습과 바뀐 색을 얹는다. 겹치는 곳(입력칸 · 헤더 지금 위치 · 조각 칸 · 끌어 놓기 칸 · 한눈에 보기 칸)은 세 번째가 이긴다. 이 문서에서 보드 이름 앞의 「접근 ·」은 세 번째 캔버스의 보드다.

**네 번째 캔버스 — 영상 같이 보기 · 보낸 추천 질문 · 상태 보드.** https://claude.ai/artifact/9QxpsbqKPbWNTw9ypVaNsL (「VA 영상 같이 보기 · 상태 보드」, 쪽 셋 · 보드 42개)가 모양의 원본이다. 사용자가 2026-10-02에 승인했다 — 플레이어는 후보 A(오른쪽 패널 맨 위), 보낸 추천 질문은 안 ②(체크 + '답 보기 →'), 상태 보드는 그대로다. ① 영상 같이 보기는 두 번째 캔버스의 결과 화면 위에 플레이어를 얹었다 — 후보 A는 Play로 재생 판 → 재생 중 → 시각을 누르면 그 시각부터 → 접기를 눌러 볼 수 있고, 도구의 variant로 YouTube(영상 4) · 로컬(영상 3)을 바꾼다. ③ 상태 보드는 이 문서와 와이어프레임이 글로만 정했거나 「캔버스에 없음」으로 그렸던 상태를 지금 코드의 모양 그대로 보드로 옮긴 것이다 — 사용자가 고칠 것 없이 확정했다. 이 문서에서 보드 이름 앞의 「같이 ·」은 네 번째 캔버스의 보드다.

대상은 한 사람이 자기 PC에서 쓰는 로컬 웹이다([[VA-INFRA-001#C5]]). 디자인은 폭 1440px 데스크톱 한 가지만 그렸다.

**도출 방법** — 사용자가 주 액터인 유스케이스([[VA-UC-001#UC-H1]]~[[VA-UC-001#UC-H8]])와 화면에 드러나는 시스템 유스케이스를 화면으로 옮겼다. 유스케이스 하나가 화면 하나는 아니다. 같은 맥락에서 이어지는 일은 한 화면에 모으고(결과 읽기 + 질문), 흐름이 끊기는 일은 나눴다(넣기 → 사전 안내 → 진행 → 결과).

**한 화면에 여러 유스케이스가 모인 곳**
- **UI-4 결과** — H3·H4가 주이고, H6·H7·H9를 여기서 연다. 요약을 읽다가 시각을 눌러 스크립트를 보고, 궁금한 것을 묻고, 다 읽으면 내보내는 것은 한 맥락이다.
- **UI-1 홈** — H1·H2·H5가 주이고, H6(행 휴지통)과 H8(첫 실행 배너)의 입구가 있다. 사용자가 하는 일이 「넣기」 아니면 「다시 열기」라 첫 화면에 둘 다 보여야 한다. 로컬 파일은 넣는 길이 둘(끌어 놓기 · inbox)이라 한 카드에 함께 둔다.
- **UI-3 분석 진행** — S2·S3·S4·S6이 한 화면의 단계 목록으로 이어진다. 사용자에게는 「분석 중」 하나다.

**유스케이스 하나가 여러 화면에 걸친 곳**

- **H8** — 키가 없다는 사실은 UI-1 배너가 알리고, 키 입력은 UI-5에서 한다.
- **S6** — 진행 상태는 UI-3에 자세히, UI-1 목록 행에 짧게 보인다. 화면을 닫아도 분석이 계속되므로 돌아갈 입구가 목록에 있어야 한다.

## 2. 화면 목록

페이지 4개(UI-1·UI-3·UI-4·UI-5), 다이얼로그 5개(UI-2·UI-6·UI-7·UI-8·UI-9). 첫 실행은 화면이 아니라 UI-1의 상태다. 파일을 끌어 오는 중 · 올리는 중도 UI-1의 상태다.

#### UI-1 홈

- **종류** 페이지. 주소 `/`
- **목적** YouTube 링크를 넣거나, 로컬 파일을 끌어 놓거나 inbox 폴더에서 골라 분석을 시작하고, 지금까지 분석한 영상을 보고 여는 첫 화면.
- **주 유스케이스** [[VA-UC-001#UC-H1]] · [[VA-UC-001#UC-H2]] · [[VA-UC-001#UC-H5]]. 여는 곳: [[VA-UC-001#UC-H6]](행 휴지통) · [[VA-UC-001#UC-H8]](첫 실행 배너). 보여 주는 곳: [[VA-UC-001#UC-S5]] · [[VA-UC-001#UC-S6]](목록 행 상태)
- **진입** 앱 시작 · 모든 페이지의 로고와 주 메뉴 '분석한 영상' · UI-3·UI-4의 '← 분석한 영상' · UI-3 실패 알림 [목록으로] · UI-2 [취소]·닫기(올린 파일 판이면 사본을 지웠다는 한 줄과 함께) · UI-5 [취소]·[저장] · UI-6 [삭제]
- **이탈** [분석] → UI-2 자막 있음 판 · [선택한 파일 분석] → UI-2 받아쓰기 필요 판 · 파일을 끌어 놓거나 [파일 고르기] → 같은 화면에서 올리는 중 → 파일 확인 중 → UI-2 올린 파일 판 · 목록 행: 완료 → UI-4, 진행 중·실패 → UI-3 · 행 휴지통 → UI-6 · 설정 아이콘·[키 넣으러 가기] → UI-5. 첫 실행 상태에서는 두 분석 버튼과 [파일 고르기]도 UI-5로 간다.

- **규칙**
  - 키가 없으면 배너를 띄우고 두 분석 버튼을 막는다. 목록은 키와 따로 정한다: 분석한 영상이 있으면 그대로 보이고, 없을 때만 빈 상태 상자를 보인다(키 없음 + 목록 0개가 첫 실행 상태). 이미 분석한 영상은 키 없이 읽을 수 있다(배너 문구). 두 분석 버튼은 막히지만 초점을 받고, 누르면 UI-5로 간다.
  - 키가 있어도 확인에 실패하면(형식 오류·인증 실패·잔액 없음) 키 없음과 같이 다룬다. 같은 배너에 '키를 확인하지 못했어요 — {이유}'를 띄우고, 분석 버튼과 UI-4 질문 입력을 막고, [키 넣으러 가기]로 UI-5에 보낸다. **인터넷이 없어 확인하지 못한 것은 문구를 가른다** — '연결을 확인하지 못했어요 — 인터넷이 되면 분석 버튼을 누를 때 다시 확인합니다'이고 [키 넣으러 가기]는 보이지 않는다. 키가 틀린 것이 아니기 때문이다(사용자 결정 2026-09-21). **이때는 분석 버튼과 질문 입력을 막지 않는다** — 누르면 서버가 그때 키를 다시 확인하고, 통과하면 배너가 사라지며 하려던 일이 이어진다. 막힌 버튼은 눌러도 요청을 보내지 않아 문구의 「누를 때 다시 확인」이 될 수 없다(API 명세 5장 11). 키는 앱이 시작할 때와 분석 버튼을 누를 때 확인한다([[VA-PRD-001#N3]], [[VA-INFRA-001#C6]]). 이 배너 문구들은 보드에 없다(8장).
  - YouTube 주소는 watch · youtu.be · shorts 세 형태를 받는다([[VA-PRD-001#R2]]). 형식이 틀리면 입력칸 아래에 바로 알리고 화면을 바꾸지 않는다([[VA-UC-001#UC-H1]] 1a, 4.5).
  - 로컬 파일을 넣는 길은 둘이다 — 끌어 놓기 칸(또는 [파일 고르기])으로 올리기와 inbox 목록에서 고르기([[VA-PRD-001#R1]], [[VA-INFRA-001#C4]]). 경로를 입력하는 길은 없다. 받는 형식은 끌어 놓기 칸 캡션에 적고, inbox 목록 아래 줄 왼쪽에는 'inbox 파일은 복사하지 않고 읽기만 해요'를 둔다. 카드 머리의 inbox 경로는 구분선 '또는 inbox 폴더에서 고르기' 옆으로 옮긴다.
  - inbox 행은 파일 이름(한 줄, 넘치면 말줄임)·길이·크기를 보인다. 목록을 주는 서버가 파일마다 길이도 알려 줘야 한다. 파일은 한 번에 하나만 고른다(aria-pressed). inbox가 비어도 끌어 놓기 칸은 그대로다.
  - **끌어 놓기는 창 어디에 놓아도 받는다.** 파일을 끌고 창에 들어오면 끌어 오는 중 덮개를 띄우고, 놓거나 창 밖으로 나가면 걷는다. 글자 · 링크처럼 파일이 아닌 것을 끌 때는 띄우지 않는다. [파일 고르기]는 브라우저의 파일 고르기 창을 여는 같은 길이고, 받는 확장자만 보이게 거른다. 키보드로는 [파일 고르기]를 쓴다 — 끌어 놓기로만 되는 일은 없다.
  - **보내기 전에 거른다.** 여러 개를 놓으면 '한 번에 한 파일씩 올려 주세요 — 파일 {n}개를 놓았어요', 받지 않는 확장자면 '{받는 형식} 파일만 받아요 — {파일 이름}는 올리지 않았어요'. 둘 다 아무것도 보내지 않는다([[VA-UC-001#UC-H2]] 1a · 1b). 앱 폴더의 디스크가 모자라면 서버가 본문을 받기 전에 거절하고 '올릴 자리가 모자라요 — {필요한 크기}가 필요한데 앱 폴더에 {남은 크기} 남았어요'(1d).
  - **올리는 동안** 칸이 올리는 중 칸으로 바뀐다. 퍼센트는 보낸 바이트 기준이고 크기는 '{보낸} / {전체}'(1 GB 이상은 GB 소수 한 자리, 아래는 MB). 올리기는 한 번에 하나다 — 그동안 [분석] · [선택한 파일 분석] · 끌어 놓기는 새 요청을 보내지 않는다(분석 버튼 대기 표시 규칙과 같다). [멈추기]를 누르면 요청을 끊고 칸 아래에 '올리기를 멈췄어요 — 올라간 부분은 지웠어요'. 새로 고침 · 창 닫기 · 앱 안의 다른 화면으로 가려 하면 먼저 묻는다 — 새로 고침 · 창 닫기는 브라우저의 확인 창(문구는 브라우저가 정한다), 앱 안의 링크는 '올리기를 멈추고 이동할까요? 올라간 부분은 지워져요.' 확인 창이다. 둘 다 브라우저 기본 창이라 그리지 않는다. 머무르면 이어 올리고, 떠나면 멈춘다. 앱 안에서 브라우저 뒤로 가기는 묻지 못해 그대로 멈춘다 — 캡션 '이 화면을 떠나면 올리기가 멈춰요'가 그것을 미리 알린다([[VA-UC-001#UC-H2]] 1e, 사용자 결정 2026-10-01). 처음에는 묻지 않고 멈췄다.
  - **다 올리면** 칸이 파일 확인 중으로 바뀌고, 서버가 길이 · 음성 트랙을 확인하고 파일 지문을 만든 뒤 등록 응답과 똑같이 갈 곳을 정한다 — 새 영상이면 UI-2 올린 파일 판, 이미 분석한 영상이면 UI-4와 '이미 분석한 영상입니다', 진행 중 · 실패면 UI-3. 같은 내용의 영상이 이미 있으면 사본은 서버가 지운다([[VA-UC-001#UC-H2]] 2c).
  - **올린 뒤에야 아는 것**(3시간 초과 · 음성 트랙 없음 · 열 수 없는 파일)은 지금처럼 UI-2 자리의 시작 불가 판으로 보인다. 사본은 서버가 이미 지웠다(2a · 2c).
  - **올리다 끊기면**(연결 · 서버 오류) '올리지 못했어요 — {이유}. 올라간 부분은 지웠어요'와 [다시 올리기]. [다시 올리기]는 같은 파일을 처음부터 올린다 — 이어 올리기는 없다([[VA-INFRA-001#C4]]).
  - 오류 · 알림 한 줄은 다음에 파일을 놓거나 고를 때, 또는 다른 분석을 누를 때 사라진다.
  - **키가 없으면 올리기 전에 막는다.** 끌어 놓기 칸이 회색이 되고 [파일 고르기]는 막힌 보조 버튼이다 — 누르면 UI-5로 간다. 놓아도 올리지 않는다. 큰 파일을 다 올린 뒤에 키 때문에 멈추지 않게 하려는 것이다. 인터넷이 없어 키를 확인하지 못한 상태는 막지 않는다(분석 버튼과 같다).
  - 분석 버튼을 누르면 서버가 영상 정보를 확인하는 동안 그 버튼에 대기 표시를 하고, 끝나면 UI-2를 연다. 시작할 수 없는 영상이면 UI-2 자리에 이유를 보인다(4.5).
  - 이미 분석한 영상을 다시 넣으면 UI-2를 열지 않는다. 완료된 영상이면 UI-4를 열고 '이미 분석한 영상입니다'를 짧게 알린다. 진행 중이거나 실패한 영상이면 UI-3을 연다([[VA-PRD-001#R7]], [[VA-UC-001#UC-S5]]). 사전 안내(UI-2)에서 취소해 작업이 없는 영상은 목록에 보이지 않고, 다시 넣으면 처음 넣은 영상처럼 UI-2를 연다(8장).
  - 목록은 최근 순이다. 머리에 '{n}개'와 고정 글자 '최근 순'. 정렬 바꾸기와 검색은 없다.
  - 행 구성: 출처 아이콘(링크 = YouTube, 필름 = 로컬 파일) · 제목(한 줄 말줄임) · 부제('YouTube · {채널}' · inbox 파일 '로컬 파일' · 올린 파일 '올린 파일') · 길이 · 상태 글자 · 휴지통. 올린 파일의 제목은 올린 원래 파일 이름이다.
  - 행 상태는 넷이고 누르면 가는 곳이 다르다([[VA-DOM-001#Video]]). 완료 → UI-4, 진행 중 → UI-3, 대기 중 → UI-3 대기 상태, 실패 → UI-3 실패 상태. 진행 중·실패 글자의 숫자는 UI-3 숫자 규칙을 따른다. 받아쓰기가 아닌 단계에서는 그 단계 이름을 쓴다.
  - 분석을 시작하면 영상이 바로 목록에 올라간다. 진행 중·실패 행에도 휴지통이 있다.
  - 진행 중 행의 작은 막대와 UI-3의 퍼센트는 같은 값을 쓴다. 보드의 40%와 38% 차이는 예시 값이다.
  - 키는 있는데 분석한 영상이 없으면 같은 빈 상태 상자를 쓰고, 설명에서 키 문장을 빼고 '위에 링크를 붙여 넣거나 파일을 끌어 놓아 보세요.'만 둔다([[VA-UC-001#UC-H5]] 1b). 첫 실행 문구도 같은 뒷부분을 쓴다.
  - 제목 아래 안내는 'YouTube 링크를 붙여 넣거나, 영상 파일을 끌어 놓거나 inbox 폴더에서 고르세요. 분석 결과는 이 PC에만 저장됩니다.'([[VA-INFRA-001#C9]]), YouTube 카드 아래 '자막이 있는 영상은 받아쓰기 없이 1분 안에 끝나요.'([[VA-PRD-001#N1]])를 둔다.
  - 입력 카드 둘은 높이를 맞추지 않고 위에 붙인다 — 「내 파일」 카드가 더 길다.
  - 헤더의 '분석한 영상' 메뉴가 현재 위치로 표시된다.

#### UI-2 사전 안내

- **종류** 다이얼로그. UI-1 위에 뜬다. 주소가 없다.
- **목적** 분석을 시작하기 전에 고른 영상의 정보, 예상 시간, 예상 비용, OpenAI로 보내는 내용을 보여 주고 시작할지 묻는다.
- **주 유스케이스** [[VA-UC-001#UC-S1]] · [[VA-UC-001#UC-H0]] 2~3번. 근거 [[VA-PRD-001#R8]]
- **진입** UI-1 [분석] → 자막 있음 판 · UI-1 [선택한 파일 분석] → 받아쓰기 필요 판 · UI-1 올리기가 끝남 → 올린 파일 판. 첫 실행 상태와 이미 분석한 영상일 때는 열리지 않는다.
- **이탈** [분석 시작] → UI-3 · [취소]·닫기(X)·Esc → UI-1. 취소하면 아무것도 전송하지 않는다. 올린 파일 판에서 취소하면 서버가 사본을 지우고, UI-1 끌어 놓기 칸 아래에 '분석을 취소했어요 — 올린 사본을 지웠어요'가 뜬다([[VA-UC-001#UC-H2]] 3a).
- **영역** 머리(제목 '분석을 시작할까요?', 부제 '걸릴 시간과 비용을 먼저 확인하세요.', 닫기) · 영상 카드(썸네일 자리 아이콘, 제목, 출처 줄, 칩) · 두 칸 카드(「예상 시간」 「예상 비용」) · 전송 안내 상자 · 버튼 줄([취소] [분석 시작]).

| 상태 | 보드 | 모습 |
|---|---|---|
| 자막 있음 | Estimate | YouTube 영상. 재생 삼각형 아이콘, 출처 줄 'YouTube · {채널}'. 칩 '길이 {길이}'(회색) + '자막 있음 · {언어}'(청록). 예상 시간 '약 1분'. 비용 '받아쓰기 (자막 사용) $0.00' + '요약 · 챕터 · 추천 질문 ${금액}'. [분석 시작] → UI-3 요약 단계부터 |
| 받아쓰기 필요 | EstimateLocal | inbox 파일. 필름 아이콘, 제목은 파일 이름, 출처 줄 '로컬 파일 · inbox'. 칩 '길이 {길이}' + '자막 없음 · 받아쓰기 필요'(둘 다 회색). 비용 '받아쓰기 {분}분 × ${단가}' + '요약 · 챕터 · 추천 질문'. [분석 시작] → UI-3 받아쓰기 중 |
| 올린 파일 | 그림 · EstimateUpload | 받아쓰기 필요 판과 같고 출처 줄만 '로컬 파일 · 올린 사본'. 버튼 줄 왼쪽에 '취소하면 올린 사본을 지워요. 원본 파일은 그대로예요.'(13px 잉크 보조 2) |

- **규칙**
  - 자막이 있으면 받아쓰기를 건너뛴다. 시간 설명은 '받아쓰기 없이 자막을 가져와 바로 요약합니다.'
  - 자막이 없으면 시간 설명은 '음성을 뽑아 {k}개 조각으로 나누고, {c}개씩 동시에 받아씁니다.' 조각 수 k와 동시 수 c는 서버가 준 값이다. 고정 문구가 아니다.
  - 자막 없는 YouTube도 받아쓰기 필요 판을 쓰고, 출처 줄만 'YouTube · {채널}'이다.
  - 예상 비용 = 받아쓰기 비용 + 요약·챕터·추천 질문 비용(추정). 큰 값은 합계에 '약'을 붙이고, 아래에 두 줄로 나눠 금액을 보인다. 받아쓰기 줄의 단가는 UI-5에서 고른 모델의 단가와 같다. 요약 비용을 어떻게 추정할지는 MINISPEC에서 정한다. [[VA-PRD-001#R8]]의 「비용 없음」 표시와 다르다(8장).
  - 예상 시간은 '약 {n}분'으로 보인다.
  - 전송 안내 상자는 무엇이 OpenAI로 가고 무엇이 안 가는지 알린다([[VA-PRD-001#N3]]). 자막 있음: 스크립트 텍스트만 OpenAI(요약 모델)로 가고 영상은 가지 않는다. 받아쓰기 필요: 받아쓰기에는 음성 조각이, 요약에는 스크립트 텍스트가 가고 영상 파일 자체는 PC 밖으로 나가지 않는다. 모델 이름은 설정 값을 쓴다.
  - 썸네일 자리는 아이콘만 둔다. 실제 썸네일 이미지는 그리지 않았다.
  - 시작할 수 없는 영상(정보 조회 실패, 3시간 초과, 음성 트랙 없음, 영상·음성 파일이 아님)은 이 다이얼로그 자리에 이유와 길이, [닫기]만 보이고 [분석 시작]은 없다([[VA-PRD-001#R2]], [[VA-PRD-001#N2]], 4.5).
  - 다른 영상이 분석 중이어도 [분석 시작]은 켜져 있다. 버튼 줄 왼쪽에 안내 한 줄 '지금 다른 영상을 분석 중이에요. 시작하면 차례를 기다렸다가 저절로 시작돼요.'를 보이고, 누르면 대기열에 들어가 UI-3 대기 상태가 열린다. 동시에 도는 분석은 하나다([[VA-PRD-001#R8]], 사용자 결정 2026-09-21).
  - 올린 파일 판의 사본 안내와 대기 안내가 함께 필요하면 두 줄로 쌓는다 — 대기 안내가 위다.
  - 올린 파일 판의 취소는 닫기(X) · Esc · 덮개 누름도 같다 — 어느 길로 닫든 사본을 지운다. 창을 닫아 남은 사본은 서버가 다음에 켜질 때 지운다([[VA-INFRA-001#C4]]).

#### UI-3 분석 진행

- **종류** 페이지. 주소 `/videos/{id}/progress`
- **목적** 분석이 지금 어느 단계에 있는지, 얼마나 남았는지, 무엇을 OpenAI로 보내는 중인지 보여 주고, 실패하면 이유와 이어서 다시 시도할 방법을 준다.
- **주 유스케이스** [[VA-UC-001#UC-S6]] · [[VA-UC-001#UC-S2]] · [[VA-UC-001#UC-S3]] · [[VA-UC-001#UC-S4]] · [[VA-UC-001#UC-S7]] · [[VA-UC-001#UC-H0]] 4~8번. 근거 [[VA-PRD-001#R8]] · [[VA-PRD-001#R12]]
- **진입** UI-2 [분석 시작] · UI-1 진행 중·실패 행 · UI-1에서 진행 중·실패한 영상을 다시 넣음 · 주소로 바로(새로 고침)
- **이탈** 끝나면 UI-4가 저절로 열린다 · '← 분석한 영상'·로고·주 메뉴·실패 알림 [목록으로] → UI-1 · 설정 아이콘 → UI-5 · 실패 알림의 다시 시도 → 같은 화면의 진행 상태
- **영역** '← 분석한 영상' · 영상 머리(44px 아이콘, 제목, '{출처} · {길이} · {자막 있음 또는 자막 없음}') · 진행 카드(헤드라인, 부제, 오른쪽 큰 퍼센트, 진행 막대, 단계 목록, 받아쓰기 단계 아래 조각 격자와 범례, 장면 단계 아래 장면 칸 줄과 캡션, 실패 때 실패 알림) · 카드 아래 줄(왼쪽 전송 표시, 오른쪽 떠나기 안내).

| 상태 | 보드 | 모습 |
|---|---|---|
| 요약 중 | Progress | 자막 있는 YouTube. 헤드라인 '핵심 요약을 만드는 중', 부제 '{m}단계 중 {i}단계 · 남은 시간 약 {n}초', 청록 퍼센트·막대, 4단계. 전송 표시 '스크립트 텍스트 → OpenAI {요약 모델}', 안내 '끝나면 결과 화면이 바로 열려요. 닫아도 분석은 계속됩니다.' |
| 받아쓰기 중 | ProgressLocal | 로컬 영상. 헤드라인 '받아쓰기 중', 부제 '조각 {n} / {m} · 남은 시간 약 {t}분', 5단계, 조각 격자(완료·받아쓰는 중·대기)와 범례. 전송 표시 '음성 조각 → OpenAI {받아쓰기 모델} · 동시 {c}개', 안내 '이 화면을 닫아도 분석은 계속돼요.' |
| 대기 중 | 없음 | 헤드라인 '차례를 기다리는 중', 부제 '앞 영상 {n}개가 끝나면 시작해요', 퍼센트 0%와 빈 막대, 단계 목록은 전부 대기 표시. 전송 표시 '아직 OpenAI로 보내는 것이 없어요', 안내 '이 화면을 닫아도 차례가 되면 시작돼요.' 차례가 오면 같은 화면이 진행 상태로 바뀐다 |

작업 단계([[VA-DOM-001#AnalysisJob]])와 화면 이름은 이렇게 맞춘다. 코드 값은 클래스 명세 초안 기준이고, 클래스 명세를 다시 쓸 때 맞춘다: `download` = 자막이면 '자막 가져오기', 아니면 '음성 내려받기' · `extract` = '음성 추출' · `transcribe` = '받아쓰기' · `summarize` = '핵심 요약' · `chapter` = '챕터' · `suggest` = '추천 질문' · `frames` = '장면' · `pending` = 첫 단계가 진행 중인 모습 · `done` = UI-4로 넘김 · `failed` = 실패 상태.

- **규칙**
  - 단계 표시는 넷이다. 완료 = 청록 원 + 흰 체크, 메모에 걸린 시간 · 진행 중 = 청록 테두리 원 + 가운데 점, 깜빡임, 이름 굵게, 메모 '진행 중' 또는 '{n} / {m}' · 실패 = 빨간 원 + 흰 X, 이름 굵게, 메모 '{k} / {m}에서 멈춤' · 대기 = 회색 빈 원, 메모 '—'. 단계 사이 연결선은 완료면 청록, 아니면 회색이고 마지막 단계에는 없다.
  - **숫자 규칙.** 진행 중 '조각 {n} / {m}'의 n은 **완료한 조각 수**다. 실패 때 '조각 {k} / {m}에서 실패'의 k는 **실패한 조각 번호**이고, 완료 수는 '완료한 {j}개는 저장됨'으로 따로 적는다. UI-1 목록 행도 같다.
  - 정상일 때 부제에 남은 시간을 보인다. 남은 시간은 작업 전체가 끝날 때까지이고, 끝난 단계가 예상보다 빨랐거나 늦었던 차이는 뒤 단계로 넘기지 않는다 — 값이 줄어들기만 한다. 받아쓰기 단계는 미완료 조각 수 × 지금까지 조각당 평균([[VA-UC-001#UC-S6]] 2번)에 요약 세 단계(핵심 요약·챕터·추천 질문)의 예상 몫을 더한다. 요약 세 단계는 그 몫에서 세 단계에 쓴 시간을 뺀다. 그 앞 단계(자막 가져오기·음성 내려받기·음성 추출·음성을 나누는 중)는 사전 안내 예상 시간에서 지난 시간을 뺀다. 0이 되면 남은 시간을 비운다. 계산은 서버가 한다.
  - 조각 격자와 범례는 받아쓰기 단계 아래에만 붙는다. 조각 하나가 칸 하나이고 한 줄에 15칸이다. 완료 청록 · 받아쓰는 중 청록 테두리에 연한 청록 안(안만 깜빡임) · 실패 빨강에 흰 × · 대기 회색(접근 · Contrast 3). 범례에 칸 수를 적고, 격자의 aria-label에 같은 내용을 글로 적는다(예: '조각 {m}개 중 {n}개 완료, {c}개 받아쓰는 중').
  - 조각 수와 동시 수는 서버 값을 그대로 보인다.
  - **장면 칸 줄**은 장면 단계 아래에만 붙는다. 챕터 하나가 칸 하나(80×45, 모서리 6px, 간격 6px, 한 줄 최대 9칸)다. 받은 칸은 그 장면 그림(바탕 잉크, 잘리지 않게 줄임), 받는 중인 칸 하나는 연한 청록 + 깜빡임, 나머지는 칩 면. 칸 줄의 aria-label은 '챕터 {m}개 중 {n}개 장면을 받음'(로컬은 '뽑음'). 메모 '{n} / {m}'의 n은 받은(뽑은) 수다.
  - **장면 단계는 실패로 바뀌지 않는다.** 장면을 못 얻으면 단계를 끝난 것으로 넘기고 UI-4가 열린다 — 결과는 장면 없이 열린다([[VA-UC-001#UC-S6]] 1b). 장면 단계에서는 빨간 표시 · 다시 시도가 없다.
  - 장면 단계의 남은 시간은 남은 챕터 수 × 지금까지 칸당 평균이다(받아쓰기 조각과 같은 방식). 계산은 서버가 한다.
  - 전송 표시는 장면 단계에서 OpenAI로 보내는 것이 없다고 알린다. YouTube는 'YouTube에서 미리 보기 썸네일 받기 · OpenAI로 보내는 것 없음', 로컬은 '원본 파일에서 프레임 뽑기 · 밖으로 보내는 것 없음'.
  - 카드 아래 전송 표시는 지금 단계에서 무엇을 어느 모델로 보내는지 알린다. 받아쓰기 단계는 음성 조각 → 받아쓰기 모델, 요약·챕터·추천 질문 단계는 스크립트 텍스트 → 요약 모델, 장면 단계는 위 규칙. 전송 사실은 시작 전(UI-2)과 진행 중(여기)에 알린다.
  - 실패하면 헤드라인·퍼센트·막대가 빨강으로 바뀌고, 부제는 남은 시간 대신 보존된 것을 알린다. 단계 목록 아래 실패 알림(role=alert)이 뜬다. 제목은 무엇이 안 됐는지, 본문은 어느 조각을 몇 번 다시 보냈고 왜 실패했는지와 무엇이 보존됐는지다(4.5).
  - 한 조각은 자동으로 3번 다시 보낸 뒤 실패로 멈춘다. 이 횟수는 MINISPEC 값과 맞춘다.
  - 다시 시도는 같은 작업을 이어간다([[VA-UC-001#UC-S3]] 3a3). 완료하지 않은 조각만 보내고, 버튼 문구와 안내의 {r}은 완료하지 않은 첫 조각 번호다. 동시에 보내므로 실패한 조각 번호 {k}와 다를 수 있다. 요약·챕터·추천 질문 단계가 실패하면 같은 알림에 '{단계}부터 다시 시도'를 둔다.
  - 화면을 닫거나 떠나도 분석은 서버에서 계속된다. 진행 내용은 1초마다 새로 받는다([[VA-INFRA-001]] 3절).
  - 분석이 끝나면 UI-4를 저절로 연다. 결과로 가는 버튼은 없다.
  - 분석 취소·중지 버튼은 없다. 멈추려면 UI-6에서 그 영상을 지운다.
  - 헤더의 두 메뉴는 현재 위치로 표시하지 않는다.

- **규칙**
  - 오른쪽 패널은 두 탭 중 하나만 보인다. 기본은 [스크립트]다. 패널 높이는 창 높이에서 헤더를 뺀 값이고, 패널 안에서 스크롤된다. 탭을 오가도 두 탭은 읽던 위치를 지킨다 — [질문하기]는 떠난 사이 새 질문 · 답이 생겼을 때만 맨 아래로 간다(7장 30).
  - 시각을 누르는 곳(인사이트 시각 칩, 챕터 카드, 답변 근거 칩, 스크립트 구간, 한눈에 보기의 막대 칸 · 인사이트 점 · 파트 띠 · 마인드맵 챕터 노드)은 모두 같은 동작이다(4.4).
  - **플레이어**(7장 32 ~ 34, [[VA-PRD-001#R14]]) — 패널 맨 위. 처음에는 재생 판이고, 누르면 그 자리에서 고른 시각(없으면 처음)부터 재생한다. YouTube는 이때 처음 플레이어를 불러온다 — 누르기 전에는 YouTube로 아무것도 가지 않는다. 연 뒤에는 시각을 누르면 그 시각부터 재생한다. 재생 위치를 따라 스크립트가 움직이지는 않는다. 접으면 멈추고 스크립트가 넓어진다. 올린 파일은 재생하지 않고 까닭 한 줄을 둔다. YouTube 시점으로 가는 링크는 여전히 내보내기(UI-7)에만 있다.
  - '원본 영상 열기'는 YouTube 결과에만 있고 새 탭으로 연다(새 탭은 보드에 없는 규칙). 로컬 파일 결과에는 없다.
  - 칩 셋: 출처('YouTube' 또는 '로컬 파일') · 길이 · 스크립트 출처와 언어('자막 · {언어}' 또는 '받아쓰기 · {언어}'). 메타 줄: '{채널 또는 로컬 파일} · {분석 시각} 분석 · {모델}'. 자막 결과는 '요약 {요약 모델}', 받아쓰기 결과는 '받아쓰기 {받아쓰기 모델}'.
  - 「한 줄 요약」은 한 문장을 큰 세리프 글자로 보인다.
  - **「한눈에 보기」**는 「한 줄 요약」과 「핵심 인사이트」 사이에 둔다 — 1440×900 창에서 결과를 열면 막대가 첫 화면 안에 든다([[VA-PRD-001]] 4장 한눈에 보기). 머리는 섹션 제목 '한눈에 보기' + 개수 '챕터 {n} · 인사이트 {k}'(파트가 있으면 '파트 {p} · 챕터 {n} · 인사이트 {k}') + 오른쪽 캡션 '누르면 오른쪽 스크립트가 그 위치로 이동해요'. 이미 만든 결과(한 줄 요약 · 인사이트 · 파트 · 챕터 · 요점)로만 그리고, 이미 분석한 영상도 다시 분석하지 않고 보인다([[VA-PRD-001#R11]]). 그림은 라이브러리 없이 HTML · CSS로 그린다([[VA-INFRA-001]] 3절).
  - **타임라인 카드**(흰 카드)는 위에서 아래로 (파트 띠) · 인사이트 점 줄 · 챕터 막대 · 시각 눈금 · 범례다. 가로 위치는 모두 영상 길이에 비례하고, 폭은 카드 안 폭 전부다.
    - 챕터 막대 — 높이 44px, 챕터마다 한 칸, 칸 폭은 챕터 길이에 비례. 칸 글자(12px 600)는 칸이 넓으면 '{번호} {제목}'(말줄임), 좁으면 번호만, 아주 좁으면 없다. 칸 바탕은 연한 청록(`#E1EFEC`) 한 톤이고 칸 사이 2px는 청록 칸막이, 막대 양 끝만 모서리 6px다 — 두 톤이 번갈던 것을 세 번째 캔버스에서 바꿨다(3.5). 마우스를 올린 칸은 `#CFE6E1`. 글자는 진한 청록. 지금 시각의 챕터 칸은 청록 바탕 · 흰 글자. 칸을 누르면 그 챕터의 시작 시각을 누른 것과 같다(4.4). aria-label '챕터 {번호} · {시작 시각} {제목}'.
    - 인사이트 점 — 26px 원(테두리 2px 청록, 흰 바탕, 두 자리 번호 Plex Mono 11px 청록)을 첫 근거 시각 자리에 둔다. 이미 놓인 점과 30px 안이면 아랫줄로 내린다(최대 세 줄). 지금 시각이 그 인사이트의 근거 시각 중 하나면 청록으로 채우고 글자는 흰색. 누르면 첫 근거 시각을 누른 것과 같다. 마우스를 올리면 바탕 `#E1EFEC`. aria-label '인사이트 {nn} · {시각}'.
    - 파트 띠 — 1시간 넘는 영상만. 막대 위 높이 30px, 파트마다 한 칸(길이 비례), 글자 '{번호} {제목}'(말줄임). 칩 면 한 톤에 칸 사이 2px는 캡션 회색(`#6B665C`) 칸막이, 양 끝만 모서리 6px이고(마우스를 올린 칸은 `#E6E1D6`), 지금 시각이 든 파트는 잉크 보조 1 바탕 · 흰 글자. 누르면 파트 시작 시각으로 간다. aria-label '파트 {번호} · {시작 시각} {제목}'.
    - 시각 눈금 — 0에서 시작해 1시간 미만 영상은 10분, 이상은 30분 간격, 끝에 영상 길이. 끝 눈금과 간격의 35% 안으로 붙는 눈금은 뺀다. 형식은 4.4.
    - 범례 — '막대 = 챕터 {n}개(길이만큼)' · '점 = 인사이트 {k}개(첫 근거 시각)'. 견본은 청록 칸막이로 나뉜 연청록 막대 조각 · 청록 테두리 원. 키보드 초점이 이 카드의 줄에 있거나 마우스가 칸을 가리키면 범례 자리에 그 칸의 이름 줄이 뜬다(4.6).
  - **마인드맵 카드**(옅은 면)는 왼쪽 뿌리에서 오른쪽으로 뻗는다. 연결선은 2px `#CFC8BB`.
    - 뿌리 — 잉크 카드(폭 150px, 모서리 14px): 라벨 '한 줄 요약'(12px 600 `#CFC8BB`)과 한 줄 요약 문장(13px, 8줄에서 말줄임).
    - 파트 없는 영상 — 뿌리 → 챕터 노드(208×52, 모서리 10px: 시작 시각 Plex Mono 12px 청록 + 제목 14px 600 한 줄 말줄임) → 요점(13px, 한 줄씩 말줄임, 최대 셋, 마우스를 올리면 전체 문장). 줄 높이 64px.
    - 파트 있는 영상 — 뿌리 → 파트 노드(폭 180px: 화살표 · '{번호}. {제목}' · '챕터 {n}개 · {시작 시각}') → 펼친 파트의 챕터 노드(높이 40px: 시각 칩 + 제목). 요점은 폭이 모자라 뺀다(7장 20). 파트 노드를 누르면 펴고 접는다 — 펼침 상태는 챕터 목록의 파트 카드와 함께 쓴다(처음에는 첫 파트만). aria-expanded.
    - 챕터 노드를 누르면 그 챕터의 시작 시각을 누른 것과 같다. 지금 시각의 챕터 노드는 청록 테두리 2px · 연한 청록 바탕.
  - **인포그래픽 카드**는 「한눈에 보기」 맨 아래에 둔다([[VA-PRD-001#R13]]). 상태는 다섯이다.
    - 만들기 전 — 점선 카드. 44px 아이콘 타일(그림) · '인포그래픽 한 장으로 보기' · '한 줄 요약 · 인사이트 · 챕터 제목으로 그림을 그려요. 한 장 약 ${값} · 누를 때만 만들어요' · 보조 버튼 [인포그래픽 만들기] → UI-8. 값은 설정 품질의 한 장 값이다.
    - 그리는 중 — 흰 카드, role=status. 연한 청록 아이콘 타일이 깜빡이고 '인포그래픽을 그리는 중이에요' · '다 되면 여기에 보여요. 그동안 결과를 계속 읽어도 돼요.' · 막힌 버튼 '그리는 중…'. 다른 화면으로 가도 서버는 계속 그린다 — 돌아오면 그리는 중이거나 다 된 모습이 보인다.
    - 다 됨 — 흰 카드. 왼쪽 그림(132×198, 세로 그림을 줄임, 누르면 UI-9) · '인포그래픽' · '{모델} · {품질} · {만든 시각} 만듦' · 안내 상자(바탕 `#F6F4EF`, 정보 아이콘) 'AI가 그린 그림이에요 — 그림 속 글자 · 숫자가 틀릴 수 있어요. 근거 시각은 인사이트와 챕터에서 확인하세요.' · '파일로 내보내면 노트에 함께 들어가요.' · 보조 버튼 [크게 보기](→ UI-9) [다시 만들기](→ UI-8).
    - 실패 — 흰 카드, 테두리 `#E8C7C0`. 위험 바탕 아이콘 타일 · '인포그래픽을 만들지 못했어요 — {이유}'(role=alert, 위험 진함) · 보조 버튼 [다시 만들기]. 이전 그림이 있었으면 이전 그림은 그대로다 — 실패 줄은 다 됨 카드 위에 한 줄로 붙는다(보드에 없음, [[VA-UC-001#UC-H9]] 4a).
    - 키 없음 — 점선 카드. 회색 열쇠 아이콘 타일 · '인포그래픽 한 장으로 보기' · 'OpenAI API 키가 없어서 지금은 만들 수 없어요.' · 주 버튼 모양 링크 [키 넣으러 가기] → UI-5. 인터넷이 없어 키를 확인하지 못한 상태는 막지 않는다(UI-1 규칙과 같다).
  - **대표 장면**은 챕터 카드 오른쪽 160×90 칸(모서리 8px, 테두리 1px `#E2DDD3`, 바탕 잉크)이다([[VA-PRD-001#R12]]). 그림은 자르지 않고 칸 안에 줄여 넣는다 — 4:3 칸(120×90)은 양옆이 어둡다. 대체 글은 '{시각} 장면'. 장면이 있으면 챕터 카드 격자가 '84px 1fr 160px'(간격 16px)가 되고, 없는 챕터는 '84px 1fr' 그대로 글이 넓어진다. 장면을 눌러도 카드를 누른 것과 같다(크게 보기 없음).
  - 장면 단계 전에 분석한 결과는 처음 열 때 서버가 뒤에서 장면을 만든다([[VA-UC-001#UC-H3]] 1a). 그동안 장면 칸 자리에 깜빡이는 칩 면 칸 '장면 가져오는 중'을 두고, 결과를 몇 초마다 다시 받아 다 된 장면부터 붙인다. 못 만들면 그 챕터는 장면 없이 넓어진다. 음성 파일 결과에는 장면 칸이 처음부터 없다.
  - 「핵심 인사이트」는 두 자리 번호(01, 02 …), 문장, 문장 끝 시각 칩 1개 이상이다. 이모지 카테고리는 붙이지 않는다. 개수는 1시간 이하 영상 5~8개, 넘으면 10개까지다([[VA-PRD-001#R4]]).
  - 추천 질문 3개가 두 곳에 같이 나온다: 본문의 큰 알약 버튼, 질문 입력칸 위의 작은 칩 줄. 어느 쪽이든 누르면 [질문하기] 탭으로 바뀌고 그 문장이 바로 전송된다([[VA-PRD-001#R9]]). 이미 물어본 것(같은 글의 질문이 기록에 있다)은 체크로 표시하고, 누르면 다시 보내지 않고 그 답으로 간다(7장 35, [[VA-UC-001#UC-H4]] 1a2). 보드는 큰 알약을 누르면 [질문하기] 탭으로 바뀌는 것까지만 그렸다. 작은 칩의 동작과 바로 전송은 보드에 없는 규칙이다.
  - 챕터 카드는 시작 시각 칩 · 제목 · 가운뎃점 요점 2~3줄 · (대표 장면)이다([[VA-PRD-001#R5]] · [[VA-PRD-001#R12]]). 보드의 1~2줄은 예시 데이터다. 머리에 '챕터 {n}개'와 안내 '누르면 오른쪽 스크립트가 그 위치로 이동해요'.
  - 영상이 1시간을 넘으면 챕터를 파트로 묶는다([[VA-PRD-001#R5]]). 머리는 '{n}개 · 파트 {m}개'. 파트 머리에 화살표 · 제목 · '챕터 {n}개' · '{시작} – {끝}'. 파트마다 따로 펴고 접고, 여러 개를 함께 펼 수 있다. 처음에는 첫 파트만 펼친다.
  - 스크립트 머리줄 왼쪽에 출처와 언어('자막(수동) · {언어}' 또는 '받아쓰기 {받아쓰기 모델} · {언어}'), 오른쪽에 선택한 시각을 보인다. 구간 줄은 시각 + 글이다 — 자막은 자막 한 줄, 받아쓰기는 15초 이하 한 토막(두세 문장)이다([[VA-INFRA-001#C3]]). 긴 영상도 조각 경계 없이 목록 하나로 보인다([[VA-PRD-001#R3]]). 수천 구간도 가상 스크롤 없이 모두 그린다 — 3시간 영상까지 충분히 빠르다([[VA-PRD-001#N2]], 카드 C 실측 · 8장).
  - [질문하기] 탭 배지는 질문 수다. 질문은 오른쪽 검은 말풍선, 답은 그 아래 문장이다. 근거가 있는 답에는 '근거'와 시각 칩이 붙는다. 근거가 없는 답은 흐린 글자에 '영상에 없는 내용' 배지가 붙는다([[VA-PRD-001#R6]]). 앞 대화에 이어 묻는 질문도 맥락 안에서 답하고, 기록은 다시 열어도 남는다.
  - 질문 기록이 0개면 점선 상자 '아직 질문이 없어요'와 '아래 추천 질문을 누르거나 직접 물어보세요. 답에는 근거가 된 시각이 함께 붙습니다.'를 보인다.
  - 입력 영역은 패널 아래에 고정이다: 추천 칩 한 줄(줄바꿈 없이, 넘치면 잘림) · 2줄 입력칸(placeholder '이 영상에 대해 물어보세요', 화면에 안 보이는 라벨 '이 영상에 질문하기') · [보내기] · '질문, 앞선 대화, 관련 스크립트가 OpenAI로 전송됩니다.'([[VA-PRD-001#N3]]). 보드 문구 '질문과 관련 스크립트가 OpenAI로 전송됩니다.'에 앞선 대화를 더했다(8장).
  - 첫 캔버스에 없던 상태는 이렇게 한다(모양은 네 번째 캔버스 ③). 답을 기다리는 동안 입력칸과 [보내기]를 잠그고 답 자리에 대기 표시를 둔다. 실패하면 답 자리에 이유와 [다시 시도]를 둔다([[VA-UC-001#UC-H4]] 2a). API 키가 없으면 입력칸을 막고 UI-5로 가는 안내를 둔다.
  - 머리의 휴지통은 흰 바탕·테두리 버튼에 빨간 휴지통 아이콘이다(4.2 테두리 아이콘 버튼, aria-label '분석 결과 삭제').
  - 헤더의 두 메뉴는 현재 위치로 표시하지 않는다.

#### UI-5 설정

- **종류** 페이지. 주소 `/settings`. 보드 높이 1820px(그림 · Settings)로 한 화면보다 길다.
- **목적** OpenAI API 키 확인·교체, 받아쓰기와 요약용 모델 선택, 인포그래픽 품질 선택, 로컬 파일이 사는 곳(inbox · 올린 사본) 확인, 밖으로 나가는 데이터 안내를 한 곳에서 보여 준다.
- **주 유스케이스** [[VA-UC-001#UC-H8]]. 근거 [[VA-PRD-001#N3]] · [[VA-PRD-001#N4]] · [[VA-INFRA-001#C6]]
- **진입** 모든 페이지의 헤더 설정 아이콘 · UI-1 첫 실행 배너 [키 넣으러 가기] · UI-3·UI-4 키 없음 배너 [키 넣으러 가기] · 첫 실행 상태의 두 분석 버튼과 [파일 고르기] · UI-4 질문하기의 키 없음 안내 · UI-4 인포그래픽 카드 키 없음 [키 넣으러 가기] · UI-8 '설정에서 바꾸기'
- **이탈** [취소]·[저장]·로고·주 메뉴 → UI-1
- **영역** 제목 '설정'과 안내 '키와 모델 설정은 이 PC에만 저장됩니다.' · 카드 다섯(「OpenAI API 키」 「모델」 「인포그래픽」 「로컬 파일」 「밖으로 나가는 데이터」) · 페이지 아래 [취소] [저장].

| 상태 | 보드 | 모습 |
|---|---|---|
| 키 확인됨 | Settings | 키 카드 머리 줄 오른쪽 끝에 청록 톤 배지 '확인됨 · {확인 시각}'. 지금 쓰는 키는 가린 값과 '.env에 저장됨'. 받아쓰기 gpt-transcribe, 요약 gpt-5.6-luna 선택 |
| 인포그래픽 · 올린 사본 | 그림 · Settings | 「모델」 아래 「인포그래픽」 카드(이미지 모델 · 품질 라디오 둘), 「로컬 파일」 카드에 `data/uploads` 줄, 표 다섯 줄. 품질 라디오는 눌러서 바뀐다 |

- **규칙**
  - 지금 쓰는 키는 앞부분과 끝 4자만 보이게 가린다. 전체를 다시 보여 주지 않는다. 입력칸이 아니라 읽기 전용 상자다.
  - 「새 키로 바꾸기」 입력칸은 password 형식이고 placeholder는 'sk-로 시작하는 키를 붙여 넣으세요'다.
  - [확인하고 저장]은 **키만** 다룬다. 가벼운 요청으로 먼저 확인하고, 통과하면 곧바로 저장하고 배지를 '확인됨 · {시각}'으로 바꾼다. 실패하면 배지를 확인 실패로 바꾸고 이유(형식 오류·인증 실패·잔액 없음)를 입력칸 아래에 보인다([[VA-UC-001#UC-H8]] 3a). 키는 저장소에 커밋되지 않는다.
  - 페이지 아래 [저장]은 **모델 선택**을 저장하고 UI-1로 간다. [취소]는 모델 변경을 버리고 UI-1로 간다. 키는 이미 [확인하고 저장]에서 저장됐으므로 [취소]가 되돌리지 않는다.
  - 웹에서 받은 키는 `.env` 파일의 그 줄에 쓴다. 지금 쓰는 키 상자의 캡션은 늘 '.env에 저장됨'이다([[VA-INFRA-001#C6]], 사용자 결정 2026-09-21). 모델 선택도 같은 파일에 쓴다.
  - 받아쓰기 모델은 gpt-transcribe 하나다. 구간 시각은 앱이 잘게 나눈 경계로 만든다([[VA-INFRA-001#C3]]) — 처음에는 시각을 주는 whisper-1 하나였다. 요약 · 챕터 · 질문 모델은 값 오름차순 여섯 — gpt-5.6-luna(첫 값) · gpt-5-mini · gpt-5.4-mini · gpt-5.6-terra · gpt-5.4 · gpt-5.6-sol 중에서 고른다(사용자 결정 2026-10-01).
  - 모델 도움말의 단가는 고른 모델의 값을 보인다(보드는 gpt-5-mini 값 하나만 있다). UI-2 예상 비용도 같은 단가를 쓴다. 모델 바꾸기는 [[VA-UC-001#UC-H8]] 5번이다.
  - **「인포그래픽」** 카드는 「모델」 아래다. 머리 오른쪽 캡션 '결과 화면에서 누를 때만 만들어요'. 왼쪽 「이미지 모델」 select(gpt-image-2 하나)와 캡션 '세로 한 장. 한 줄 요약 · 인사이트 · 챕터 제목만 보내요'. 오른쪽 「품질」 라디오 둘(radiogroup, 한 줄 48px 칸: 고름 청록 테두리 · 연한 청록 바탕) — '낮음 (기본)' + '한 장 약 ${낮음 값}', '중간' + '한 장 약 ${중간 값}'. 아래 캡션은 고른 품질을 따른다 — 낮음 '값이 가장 싸요. 그림 속 작은 글자는 흐릴 수 있어요.', 중간 '글자가 더 또렷해요. 값은 낮음의 약 {배}배예요.' 값은 서버가 주는 품질별 한 장 값이다(지금 $0.01 · $0.05, [[VA-PRD-001#R13]]). 품질은 페이지 [저장]으로 모델 선택과 함께 `.env`에 저장한다([[VA-INFRA-001#C6]]).
  - **「로컬 파일」** 카드(첫 캔버스의 「로컬 파일 폴더」)는 읽기 전용 값 상자 둘이다 — inbox 경로 + '읽기 전용', `data/uploads` + '끌어 놓은 파일의 사본 · 분석이 끝나면 지워요'. 바꾸는 입력칸은 없다. 안내 'inbox 폴더의 파일은 읽기만 하고 고치거나 지우지 않아요. 화면에 끌어 놓은 파일은 원본을 그대로 두고 앱 폴더의 사본으로 분석해요. inbox 위치는 docker-compose.yml에서 바꿀 수 있습니다.'([[VA-INFRA-001#C4]]).
  - 「밖으로 나가는 데이터」 표는 아래 여섯 줄이고, 끝에 '원본 영상 파일, 분석 결과, API 키는 이 PC 밖으로 나가지 않습니다.'를 둔다. 이 목록은 [[VA-PRD-001#N3]]·[[VA-INFRA-001#C9]]보다 넓다(8장).

#### UI-6 삭제 확인

- **종류** 다이얼로그(경고 다이얼로그). 주소가 없다.
- **목적** 분석 결과를 지우기 전에 무엇이 지워지고 무엇이 남는지 보여 주고 한 번 더 확인받는다.
- **주 유스케이스** [[VA-UC-001#UC-H6]]. 근거 [[VA-PRD-001#R7]]
- **진입** UI-1 목록 행 휴지통(aria-label '{제목} 분석 결과 삭제') · UI-4 머리 휴지통(aria-label '분석 결과 삭제')
- **이탈** [삭제] → UI-1(그 행이 사라진 목록) · [취소]·Esc → 연 화면 그대로(UI-1 또는 UI-4). 보드는 UI-1 위에 한 판만 그려 두 버튼 모두 UI-1로 이어져 있다.
- **영역** 빨간 톤 휴지통 아이콘 타일 · 제목 '분석 결과를 지울까요?' · 지울 영상 제목 · 두 칸(왼쪽 빨간 톤 「지워지는 것」, 오른쪽 회색 톤 「남는 것」) · 버튼 줄([취소] [삭제]).

| 상태 | 보드 | 모습 |
|---|---|---|
| 완료된 YouTube 영상 | Delete | 지워지는 것 '스크립트, 핵심 요약, 챕터, 추천 질문, 질문 기록 {n}개', 남는 것 'YouTube 원본 영상. 다시 넣으면 처음부터 분석합니다.' |
| 올린 파일, 실패해 사본이 남음 | 그림 · DeleteUpload | 지워지는 것 '스크립트, 핵심 요약, 챕터, 추천 질문, 질문 기록 {n}개, 임시 음성 파일, 올린 사본({크기})', 남는 것 'PC에 있는 원본 파일. 다시 넣으면 처음부터 분석합니다.' |

- **규칙**
  - 제목 바로 아래 지울 영상의 제목을 보이고, 다이얼로그 설명(aria-describedby)으로 잇는다.
  - 「지워지는 것」은 스크립트, 핵심 요약, 챕터, 추천 질문, 질문 기록 {n}개다. 대표 장면이 있으면 '대표 장면', 인포그래픽을 만들었으면 '인포그래픽'을 챕터 뒤에 더한다. 분석이 끝나지 않은 영상(진행 중·실패)이면 '임시 음성 파일'을 더하고, 올린 사본이 아직 남아 있으면 '올린 사본({크기})'을 맨 끝에 더한다([[VA-UC-001#UC-H6]]).
  - 「남는 것」은 YouTube면 'YouTube 원본 영상', inbox 파일이면 'inbox 원본 파일', 올린 파일이면 'PC에 있는 원본 파일'이다. 뒤에 '다시 넣으면 처음부터 분석합니다.'를 붙인다([[VA-INFRA-001#C4]]). 내보낸 노트 · 그림 파일도 남지만 문구에는 적지 않는다.
  - 진행 중인 영상을 지우면 작업을 먼저 멈추고 지운다. 실패한 영상은 보존된 조각까지 지운다.
  - 되돌릴 수 없는 동작이다. [삭제]는 빨간 위험 버튼, [취소]는 보조 버튼이다.
  - 닫기(X)는 없다. 바깥을 눌러도 닫히지 않는다. 처음 초점은 [취소]에 둔다(4.3).

- **종류** 다이얼로그. UI-4 위에 뜬다. 주소가 없다.

  - 형식은 마크다운이다. 파일로 저장하면 노트와 스크립트 파일 둘을 쓰고, 복사하면 노트만 넣는다([[VA-PRD-001#R10]]).
  - 방법은 둘 중 하나만 고른다(aria-pressed). 기본은 파일로 저장이다. 주 버튼 글자가 고른 방법을 따라간다.
  - 파일로 저장하면 서버가 노트를 `data/export/{파일 이름}.md`에, 스크립트를 `data/export/{파일 이름} 스크립트.md`에 쓴다. 칸 아래에는 노트 경로 하나를 보인다(보드 그대로). 브라우저 다운로드는 두지 않는다. 파일 이름은 영상 제목에서 만들고, 만드는 규칙은 MINISPEC에서 정한다.
  - 체크박스 '질문 기록 {n}개도 넣기'는 기본으로 꺼져 있다. n은 UI-4 [질문하기] 배지 수와 같다.
  - 내용 순서: `# {제목}` → `원본: {링크} · {길이}` → `> {한 줄 요약}` → `## 한눈에 보기`(파일로 저장이고 인포그래픽이 있으면 `![[{파일 이름} 인포그래픽.png]]`, 이어서 Mermaid `gantt` — 챕터 구간 · 파트 구역 · 인사이트 이정표 — 와 Mermaid `mindmap` — 한 줄 요약 → (파트 →) 챕터 → 요점. 파트가 있으면 화면 마인드맵처럼 요점을 뺀다(7장 20)) → `## 핵심 인사이트` 번호 목록(문장 끝에 시각) → `## 챕터`(챕터마다 `### [{시각}]({링크}) {제목}`, 파일로 저장이고 장면이 있으면 `![[{파일 이름} {시각}.jpg]]`, 그리고 `- {요점}`) → 파일로 저장할 때만 `## 스크립트`와 스크립트 파일을 가리키는 `[[{파일 이름} 스크립트]]` 한 줄 → 체크하면 질문 기록. 스크립트 줄은 노트에 없고 스크립트 파일에 있다([[VA-PRD-001#R10]]). 질문 기록은 미리 보기가 잘려 보드에 보이지 않는다. Mermaid로 그리는 법(글자 이스케이프 · 눈금 형식)은 MINISPEC이 정한다([[VA-PRD-001#R11]]).
  - **그림 파일**은 파일로 저장할 때만 노트와 같은 `data/export/`에 쓴다 — 장면 `{파일 이름} {시각}.jpg`(시각의 쌍점은 하이픈, 예 `09-51`), 인포그래픽 `{파일 이름} 인포그래픽.png`. 같은 이름이 있으면 덮어쓴다(노트 · 스크립트와 같다). 클립보드 복사에는 그림 파일도 그림 줄도 넣지 않는다 — 가리킬 파일이 없다. 한눈에 보기 Mermaid 절은 복사에도 들어간다.
  - 미리 보기는 고른 방법의 내용이다 — 파일로 저장과 복사의 미리 보기가 그림 줄만큼 다르다. 보드의 '새로 들어가는 것' 줄은 검토용이라 옮기지 않는다.
  - 시각은 `[MM:SS]`(1시간 이상 영상은 `[H:MM:SS]`, 4.4를 따른다) 텍스트로 남는다. YouTube 영상이면 `https://youtu.be/{영상ID}?t={초}` 링크가 걸리고, 로컬 파일이면 링크 없이 시각만 남는다.
  - 미리 보기는 실제로 내보낼 내용의 앞부분이다. 높이 280px이고 안에서 스크롤된다(첫 캔버스의 220px에서 늘림). 체크박스를 바꾸면 따라 바뀐다(보드에 없는 규칙).
  - 주 버튼을 누르면 다이얼로그를 닫고 UI-4에서 완료를 짧게 알린다([[VA-UC-001#UC-H7]] 3번). 알림 모양은 네 번째 캔버스 ③의 보드다 — 창 아래 가운데.
  - 두 번째 캔버스의 다이얼로그는 위 여백 48px · 안쪽 28px 32px · 세로 간격 18px이다 — 파일 목록 줄이 늘어 1440×960 창에 들게 줄였다.

#### UI-8 인포그래픽 만들기

- **종류** 다이얼로그. UI-4 위에 뜬다. 주소가 없다.
- **목적** 인포그래픽을 그리기 전에 예상 비용과 OpenAI로 보낼 내용을 보여 주고 확인받는다. 돈이 드는 동작이라 UI-2처럼 한 번 묻는다(7장 22).
- **주 유스케이스** [[VA-UC-001#UC-H9]] 1~3번. 근거 [[VA-PRD-001#R13]] · [[VA-PRD-001#N3]]
- **진입** UI-4 인포그래픽 카드 [인포그래픽 만들기] · [다시 만들기]. 키가 없으면 카드가 키 없음 상태라 열리지 않는다.
- **이탈** [만들기 · 약 ${값}] → UI-4(카드가 그리는 중) · [취소]·닫기(X)·Esc·덮개 → UI-4 그대로 · '설정에서 바꾸기' → UI-5
- **영역** 머리(제목 '인포그래픽 만들기', 부제 '이 영상의 내용을 그림 한 장으로 그려요.', 닫기) · 두 칸(「예상 비용」 '약 ${값}' Plex Mono 22px · 「품질」 '{낮음 또는 중간} · {이미지 모델}' 17px 600 + 링크 '설정에서 바꾸기') · 보내는 것 상자(테두리 1px, '↗ OpenAI로 보내는 것' 14px 600 · '한 줄 요약 1문장 · 인사이트 {k}개 · 챕터 제목 {n}개' · '스크립트 전체는 보내지 않아요. 그림 속 글자 · 숫자는 틀릴 수 있어요.') · 버튼 줄([취소] [만들기 · 약 ${값}]).

| 상태 | 보드 | 모습 |
|---|---|---|
| 처음 만들기 | 그림 · Infographic | 42분 YouTube 결과 위. 인사이트 8개 · 챕터 제목 8개 |

- **규칙**
  - 값은 설정에서 고른 품질의 한 장 값이다(서버 값, UI-5와 같다).
  - 보내는 것은 한 줄 요약 · 인사이트 · 챕터 제목뿐이다. 스크립트 전체는 보내지 않는다([[VA-UC-001#UC-H9]] 4번).
  - 이미 그림이 있으면(다시 만들기) 보내는 것 상자 아래에 '새 그림이 지금 그림을 바꿔요.'를 더한다(보드에 없음, [[VA-UC-001#UC-H9]] 5a).
  - [만들기]를 누르면 다이얼로그를 닫고 카드가 곧바로 그리는 중이 된다. 실패는 카드의 실패 상태로 알린다(UI-4 규칙).
  - 폭 580px, 위 여백 120px. 처음 초점은 [만들기](4.3).

#### UI-9 인포그래픽 크게 보기

- **종류** 다이얼로그. UI-4 위에 뜬다. 주소가 없다.
- **목적** 만든 인포그래픽을 크게 본다.
- **주 유스케이스** [[VA-UC-001#UC-H9]] 5번
- **진입** UI-4 인포그래픽 카드의 그림 · [크게 보기]

- **영역** 머리(제목 '인포그래픽' 18px 600, 부제 '{모델} · {품질} · {만든 시각} 만듦', 닫기) · 그림(가운데, 폭 432px로 줄임) · 안내 'AI가 그린 그림이에요 — 그림 속 글자 · 숫자가 틀릴 수 있어요.'

| 상태 | 보드 | 모습 |
|---|---|---|
| 다 된 그림 | 그림 · InfographicView | 42분 YouTube 결과 위. 그림은 자리 표시 |

- **규칙**
  - 덮개는 다른 다이얼로그보다 짙다(`rgba(27, 26, 23, 0.72)`) — 그림을 보는 화면이라 뒤가 덜 보이게.
  - 그림은 세로 한 장(1024×1536)을 폭 432px로 줄여 보인다. 창이 낮으면 창 높이에 맞춰 더 줄인다(보드에 없음). 대체 글은 '인포그래픽 — {영상 제목}'.
  - 내려받기 버튼은 없다 — 파일로 내보내면 노트 곁에 저장된다(UI-7).
  - 폭 640px, 위 여백 48px, 안쪽 24px. 처음 초점은 닫기(X).

**세 번째 캔버스가 바꾼 곳** — 새 색은 잉크 hover `#3A3731` 하나다. 이름과 쓰는 곳이 바뀐 값: 메뉴 현재 위치 → hover 바탕(`#EAE6DD`) · 막대 둘째 톤 → 연한 청록 hover(`#CFE6E1`) · 파트 띠 둘째 톤 → 파트 띠 hover(`#E6E1D6`) · 받아쓰는 중 조각 → 중간 청록(`#8FC7BE`). 쓰는 곳이 는 값: 흐린 표시선(입력칸 · select · 채팅 입력 상자 테두리, 끌어 놓기 칸 점선) · 강조 청록(초점 고리, 받아쓰는 중 조각 테두리, 막대 칸막이) · 캡션(파트 띠 칸막이) · 연한 청록(받아쓰는 중 조각의 안) · 위험 진함 · 위험 가장 진함 · 위험 바탕(hover). 헤더 지금 위치는 바탕 대신 잉크 밑줄이다(4.1).

**색 언어.** 바탕은 따뜻한 회색 단계이고 강조색은 **청록 하나**다. 청록은 누를 수 있는 시각, 지금 선택·위치, 진행과 완료, 키보드 초점 고리에만 쓴다. **빨강은 위험과 실패에만** 쓴다(삭제, 멈춘 분석, 키 없음). **노랑은 선택한 스크립트 구간 하나에만** 쓴다. 장식으로 색을 쓰지 않고, 카드는 그림자 대신 1px 선으로 나눈다.

### 3.4 움직임

움직이는 것은 **「지금 하는 중」 깜빡임 하나**다. 분석 화면은 몇 분에서 십여 분 켜 두므로 멈추지 않았다는 것만 알린다.

```css
@keyframes va-pulse { 0%, 100% { opacity: 1; } 50% { opacity: 0.4; } }
.va-pulse { animation: va-pulse 1.4s ease-in-out infinite; }
@media (prefers-reduced-motion: reduce) { .va-pulse { animation: none; } }
```

- 붙이는 곳: UI-3 진행 중 단계 표시 · 받아쓰는 중인 조각 칸의 안(청록 테두리는 깜빡이지 않는다) · 받는 중인 장면 칸, UI-1 파일 확인 중 막대, UI-4 '장면 가져오는 중' 칸 · 인포그래픽 그리는 중 아이콘. 모두 「지금 하는 중」이다. 완료·실패·대기에는 없다.
- 운영체제에서 움직임 줄이기를 켜면 깜빡임을 끈다. 색과 모양만 남는다.
- 그 밖에는 애니메이션과 transition이 없다. 파트 화살표 회전(0도 ↔ 90도), 링크 hover 색 바뀜, 버튼 · 행 hover(4.2), 초점 고리(4.6), 탭 전환, 시각 선택 강조는 모두 바로 바뀐다.

- **실패 조각** — 완료 조각과 밝기가 같아(1.08:1) 색으로만 갈렸다. 가운데에 흰 ×를 넣는다.
- **입력칸 · select · 채팅 입력 상자 테두리** — 흐린 표시선 `#948D80`으로 올린다. 입력칸이 놓이는 카드 · 옅은 면에서 3:1을 넘는다.
- **보조 버튼 · 알약 테두리** — 그대로 둔다. 글자가 무엇인지 알려 주어 테두리는 꾸밈이다. 마우스를 올리면 바탕이 진해진다(4.2). 버튼까지 3:1로 올리려면 바탕 `#F6F4EF` 위 버튼(UI-4 머리) 때문에 `#948D80`(2.99:1)보다 진한 값이 필요하다.
- **선택 챕터 테두리** — 스크립트 구간의 노란 강조가 두 번째 신호라 그대로 둔다.
- **헤더 지금 위치** — 바탕 대신 헤더 아래선 자리의 잉크 밑줄 2px(4.1). `aria-current="page"`도 그대로다.
- **카드 테두리·구분선·요점 점** — 장식이라 기준 밖이다. 요점 점은 aria-hidden이다.
- **막대 칸 · 파트 띠 칸** — 한 톤으로 칠하고 칸 사이 2px를 칸막이 색(막대 청록 · 띠 캡션)으로 채운다. 번호 글자 · aria-label · 아래 챕터 목록도 그대로 준다. 둘째 톤은 hover에 쓴다.
- **끌어 놓기 칸 점선** — 파일을 받는 자리라 입력칸과 같은 `#948D80`. 키 없음(막힌 칸)은 쓸 수 없는 것이라 기준 밖이고, 빈 상태 상자 · 인포그래픽 카드 점선은 받는 자리가 아니라 그대로다.
- **그림 실패 테두리** — 장식이다. 실패는 빨간 아이콘과 이유 문장이 알린다.

### 4.1 앱 셸

- **헤더** — 높이 64px. 왼쪽 로고(검은 30×30 타일 안 재생 삼각형 + 'Video Agent', → UI-1). 오른쪽 주 메뉴(nav, aria-label '주 메뉴'): 글자 메뉴 '분석한 영상'(→ UI-1)과 설정 아이콘 버튼(aria-label '설정', → UI-5). 로그인·계정 메뉴는 없다([[VA-INFRA-001#C5]]).
- **현재 위치 표시** — 글자 `#1B1A17` + 헤더 아래선 자리의 잉크 밑줄 2px(그 메뉴 폭) + `aria-current="page"`. 아닌 메뉴는 글자 `#4A463F`이고 밑줄이 없다. 바탕은 hover에만 쓴다(4.2). 세 번째 캔버스 전에는 바탕 `#EAE6DD`였다 — 헤더 바탕과 1.13:1이라 바꿨다(3.5). `aria-current="page"`는 Settings 보드에만 그렸고, UI-1 메뉴에도 코드에서 붙인다.

| 화면 | 현재 위치로 표시하는 메뉴 |
|---|---|
| UI-1 홈 | '분석한 영상' |
| UI-3 분석 진행 · UI-4 결과 | 없음 |
| UI-5 설정 | 설정 아이콘 |

- **사이드바는 없다.** 페이지가 넷이고 오가는 길이 헤더와 뒤로 링크로 충분하다.
- **뒤로 링크** — UI-3·UI-4 본문 맨 위에 '← 분석한 영상'(→ UI-1).
- **스크롤** — 헤더는 창 위에 남고, 그 아래 내용 영역이 스크롤된다. UI-4 오른쪽 패널은 내용 영역 안에서 고정되고 높이는 창 높이 − 64px이다. 보드는 패널만 sticky로 그렸고, 헤더 고정은 패널 높이 896px(= 960 − 64)에서 이끈 규칙이다.
- **키 없음 배너** — 헤더 위에 전체 폭으로 붙는다(4.5).
- **폭** — 1440px 창을 기준으로 그렸다. 좁은 창은 그리지 않았다(8장).

- **바뀌지 않는 것** — 고른 것(고른 파일 행 · 내보내기 선택지 · 품질 줄, 고른 챕터 카드, 고른 스크립트 구간, 지금 챕터 칸 · 지금 파트 · 채운 인사이트 점, 지금 위치 메뉴의 밑줄), 막힌 버튼(`aria-disabled`), 그리는 중 버튼. 고른 것과 hover가 헷갈리지 않는다.
- **목록 행** — 행 전체(행 링크 + 휴지통)에 띠를 깐다. 글자 자리는 그대로 두고 띠만 양옆으로 12px 넓히고 모서리 10px. 휴지통에 올리면 휴지통만 빨갛게 바뀐다.
- 챕터 카드 · 파트 안 챕터 노드의 시각 표시는 칩 모양일 뿐이라 따로 바뀌지 않고 카드 hover를 따른다.
- 누를 수 있는 것은 모두 `cursor: pointer`다. 막힌 버튼은 지금처럼 둔다.

### 4.3 다이얼로그

- **덮개** — 뒤 페이지 전체를 `rgba(27, 26, 23, 0.52)`로 덮는다. 다이얼로그는 가로 가운데, 세로는 위에 붙인다(위 여백은 3.3).
- **틀** — 바탕 `#FFFFFF` · 안쪽 32px · 모서리 18px · 그림자 `0 28px 80px rgba(27, 26, 23, 0.32)` · `aria-modal="true"` · 제목에 `aria-labelledby`. UI-2·UI-7·UI-8·UI-9는 `role="dialog"`, UI-6은 `role="alertdialog"`. UI-9 덮개는 더 짙다(3.1).
- **머리** — 제목 묶음(Hahmlet 제목 + 15px `#5E5A52` 부제, 간격 6px)과 오른쪽 닫기 아이콘 버튼(aria-label '닫기'). UI-6은 닫기 대신 왼쪽 위에 48×48px 빨간 톤 휴지통 타일을 두고, 제목 아래 설명을 `aria-describedby`로 잇는다.
- **닫기 동작**

| 동작 | UI-2 사전 안내 | UI-6 삭제 확인 | UI-7 내보내기 | UI-8 인포그래픽 만들기 | UI-9 크게 보기 |
|---|---|---|---|---|---|
| 닫기(X) | 있음 = 취소 | 없음 | 있음 = 취소 | 있음 = 취소 | 있음 |
| Esc | 취소 | 취소 | 취소 | 취소 | 닫기 |
| 덮개(바깥) 누름 | 취소 | 닫히지 않음 | 취소 | 취소 | 닫기 |
| 처음 초점 | [분석 시작] | [취소] | 고른 방법 칸 | [만들기] | 닫기(X) |

닫기(X)가 있는지 없는지만 보드에 있다. Esc·덮개 누름·처음 초점은 보드에 없고 이 문서가 정한 규칙이다.

- **버튼 순서** — 바닥 줄 오른쪽 정렬, 간격 10px. 왼쪽이 [취소](보조), 오른쪽 끝이 확인 동작(주 버튼 또는 위험 버튼). 버튼 줄 왼쪽에는 안내 한 줄이 올 수 있다(UI-2 대기 · 올린 사본).
- **초점** — 열리면 초점이 다이얼로그 안으로 들어가고 밖으로 나가지 않는다. 닫히면 연 버튼으로 돌아간다.
- **주소** — 다이얼로그는 주소를 바꾸지 않는다. 뒤 페이지는 그대로 남는다.

### 4.4 시각 표기

- **형식은 영상 길이로 정한다.** 1시간 미만 영상은 `mm:ss`(12:40), 1시간 이상 영상은 `h:mm:ss`(0:06:20). 한 영상 안에서는 모든 시각이 같은 형식이다. 영상 길이 자체도 같은 규칙이다(50:12, 2:30:00).
- **어디서든 같은 컴포넌트**(시각 칩, 4.2)를 쓴다. 스크립트 구간 줄의 시각은 칩이 아니라 줄 전체가 버튼이다. 챕터 카드도 같다 — 시각은 칩 모양만 같고 카드 전체가 버튼이다.
- **시각을 누르면**(인사이트 시각 칩, 챕터 카드, 답변 근거 칩, 스크립트 구간, 한눈에 보기의 막대 칸 · 인사이트 점 · 파트 띠 · 마인드맵 챕터 노드):
  1. 오른쪽 패널이 [스크립트] 탭으로 바뀐다.
  2. 그 시각이 든 스크립트 구간이 노란 바탕(`#F8EDC4`)과 진한 노랑 시각(`#7A5A00`)으로 강조된다. 그 구간이 패널에 다 보이지 않을 때만 패널 가운데로 스크롤된다 — 이미 보이면 움직이지 않는다(스크롤은 보드에 없는 규칙, 7장 29).
  3. 시작 시각이 같은 챕터 카드가 흰 바탕 + 청록 테두리(`#9CCBC3`)로 바뀐다. 한눈에 보기에서는 그 시각이 든 챕터의 막대 칸과 마인드맵 노드, 그 시각이 든 파트 띠가 함께 바뀌고, 그 시각이 근거인 인사이트 점이 채워진다 — 같은 챕터가 세 곳에서 함께 강조된다.
  4. 스크립트 머리줄 오른쪽 시각이 그 시각으로 바뀐다.
  5. 플레이어가 열려 있으면 그 시각부터 재생한다(7장 32). 열기 전이나 접혀 있으면 재생하지 않는다.
- 선택은 한 번에 하나다. 선택이 없는 카드와 줄은 바탕·테두리가 투명하다.
- 고른 시각은 결과 화면 주소에 `?t={초}`로 남는다 — 새로 고치거나 다른 화면에 다녀와도 같은 시각을 고른 채로 열린다. 주소만 바꿔 써서 방문 기록은 늘지 않는다(7장 29).
- 파트 띠와 인사이트 점은 그 시작 시각 · 첫 근거 시각을 누른 것과 같다. 마인드맵의 파트 노드는 시각이 아니라 펴고 접기다.
- 시각 칩은 UI-4에서만 쓴다. UI-1 목록·inbox 행의 길이와 UI-3 단계 메모(걸린 시간·조각 수)는 누를 수 없는 고정폭 글자다. UI-2·UI-4 메타 칩과 UI-3 부제·영상 머리 안의 길이·조각 수는 일반 UI 글자(Plex Sans KR)다.
- 결과 화면에서 시각은 YouTube 사이트로 가지 않는다 — 플레이어가 열려 있으면 화면 안에서 그 시각부터 재생한다. 내보낸 마크다운에서만 `[시각](https://youtu.be/{영상ID}?t={초})` 링크가 된다(UI-7). 결과 화면 주소의 `?t=`는 이 앱 안의 위치다.

별도 오류 페이지는 없다. 오류는 생긴 자리에 보인다.

### 4.6 접근성

- **누르는 영역** — 기본 44px 이상. 예외(시각 칩 26px, 작은 추천 칩 32px, 보내기 40px, 배너 버튼 40px, '원본 영상 열기' 링크 24px)도 WCAG 2.2 최소 24px 이상이다. '원본 영상 열기'는 보드에서 높이를 정하지 않았으므로 코드에서 최소 높이 24px를 준다(3.3).
- **진짜 요소** — 이동은 링크(`a`), 동작은 `button`. 보드가 `a`로 그린 버튼([분석 시작] [저장] 등)도 이 규칙으로 옮긴다. 목록 행은 행 전체가 링크이고 휴지통은 따로 된 버튼이다.
- **이름** — 아이콘만 있는 버튼에 aria-label: '설정' · '닫기' · '보내기' · '분석 결과 삭제' · '{제목} 분석 결과 삭제'. 시각 칩은 '{시각} 위치의 스크립트로 이동'. 채팅 입력칸은 숨은 라벨 '이 영상에 질문하기'.
- **상태 알리기** — 파일 행·내보내기 선택지 `aria-pressed` · 파트 머리 `aria-expanded` · 헤더 현재 위치 `aria-current="page"` · 첫 실행 분석 버튼 `aria-disabled="true"` · 진행 카드 `aria-live="polite"` · 실패 알림 `role="alert"` · 키 없음 배너 `role="status"` · 조각 격자 `role="img"`와 글 설명.
- **탭** — 보드는 `aria-pressed`로 그렸다. 코드에서는 `tablist` · `tab` · `aria-selected`로 옮긴다.
- **초점 고리** — 누를 수 있는 모든 것에 같은 고리를 쓴다(세 번째 캔버스 ①): 청록 `#0F6E68` 2px를 2px 띄워서(`outline` · `outline-offset`), 모서리는 그 요소를 따른다. 앱이 쓰는 바탕 위에서 모두 3:1을 넘는다(3.5).
  - Tab으로 올 때만(`:focus-visible`) 보인다. 입력칸 · select · 채팅 입력은 글을 쓸 자리라 마우스로 눌러도 보인다(브라우저 규칙 그대로).
  - 카드 가장자리까지 꽉 찬 줄은 바깥 고리가 잘리거나 겹쳐 안쪽에 그린다 — 파트 머리는 4px 안쪽(파트 카드가 모서리를 자른다), 결과 탭은 2px 안쪽(탭 바 아래선에 닿는다).
  - 채팅 입력은 textarea가 아니라 상자 전체(보내기 포함)에 고리를 두른다. 작은 추천 칩 줄은 위아래 4px 여유를 두어 칩의 고리가 잘리지 않게 한다.
  - 고른 것(청록 채움 · 노란 구간 · 흰 카드 · 지금 위치 밑줄)과 초점은 따로 보인다 — 둘이 겹쳐도 고리는 그대로 바깥에 그린다.
  - 한눈에 보기 칸처럼 붙어 놓인 칸은 초점을 받은 칸을 이웃 칸 위로 올려 그린다 — 바깥 고리가 다음 칸에 덮이지 않게(카드 E5 코드 리뷰).
- **가리지 않게** — 헤더(와 키 없음 배너)는 창 위에 붙어 있다. Tab으로 옮긴 곳이 그 밑에 숨지 않게 스크롤 여백을 헤더(+배너) 높이 + 16px로 둔다(WCAG 2.2 2.4.11).
- **움직임** — `prefers-reduced-motion: reduce`면 깜빡임을 끈다(3.4).
- **대비** — 3.5 표를 따른다. 색만으로 정보를 주지 않는다(상태 글자, 범례 숫자, 아이콘 모양이 함께 간다).
- **끌어 놓기** — 끌어 놓기로만 되는 일은 없다. 키보드와 화면 읽기 프로그램은 [파일 고르기]로 같은 일을 한다. 끌어 오는 중 덮개는 보이기만 하고 초점을 받지 않는다. 올리는 중 칸은 `aria-live="polite"`.
- **한눈에 보기** — 막대 칸 · 인사이트 점 · 파트 띠 · 마인드맵 노드는 진짜 `button`이고 aria-label에 번호 · 시각 · 제목을 적는다. 파트 노드는 `aria-expanded`. 요점의 전체 문장은 `title`로도 준다. 장면 그림 alt '{시각} 장면', 인포그래픽 alt '인포그래픽 — {영상 제목}'.
- **한눈에 보기 키보드**(세 번째 캔버스 ④) — 파트 띠 · 인사이트 점 · 챕터 막대는 줄마다 Tab이 한 번 멈춘다(`role="toolbar"`, 이름 '파트 띠' · '인사이트 점' · '챕터 막대'). 줄 안에서는 ← →로 앞뒤 칸, Home · End로 처음 · 끝 칸으로 초점을 옮기고 끝에서 멈춘다. 점은 시각 차례(왼쪽에서 오른쪽, 같은 시각이면 번호 차례)로 옮긴다 — 인사이트 번호는 모델이 정한 차례라 시각과 다를 수 있다(카드 E5 코드 리뷰). 옮기기만 하고 시각은 바뀌지 않는다 — Enter · Space가 그 칸을 누른 것과 같다. 줄에 들어오면 지금 고른 칸(없으면 첫 칸)에서 시작한다.
  - **가리킨 칸 이름** — 키보드 초점이 이 줄들에 있거나 마우스가 칸을 가리키면, 범례 자리에 그 칸의 이름 줄을 보인다: '챕터 {번호}' · 시각(Plex Mono 청록) · 제목(말줄임). 파트는 '파트 {번호}', 인사이트는 '인사이트 {nn}'과 문장 앞부분. 키보드일 때는 끝에 '← → 옮기기 · Enter 이동'(캡션). 좁은 칸은 칸 안에 이름이 들어가지 않아서다. 키보드와 마우스가 함께 가리키면 마지막으로 가리킨 쪽을 보이고, 그 쪽이 거두어지면(마우스가 카드를 나가거나 초점이 줄을 떠나면) 남은 쪽을 보인다. 마우스가 카드 안에 있는 동안은 마지막으로 가리킨 칸이 남고(WCAG 1.4.13), Esc로 닫는다. 화면 읽기 프로그램은 칸의 aria-label을 읽으므로 이 줄은 `aria-hidden`이다.
- **결과 탭** — 두 탭(`tablist`)은 탭 하나가 Tab 한 번이고 ← →로 옮긴다. 옮기면 그 탭이 바로 열린다.
- **언어** — 문서 언어는 `ko`.

## 7. 판단이 필요한 지점

**1. 결과 화면 배치 — 결정: 두 열, 오른쪽에 고정 패널과 탭([스크립트] | [질문하기]).**
이유: 시각을 누를 때마다 스크립트가 바로 보여야 한다. 3시간 스크립트(수천 구간)를 요약 아래에 두면 요약과 챕터가 밀려나고, 누를 때마다 페이지가 멀리 뛴다([[VA-PRD-001#N2]]). 질문과 스크립트는 둘 다 「본문을 읽다가 옆에서 확인하는 것」이라 한 패널의 탭으로 묶었다. 답의 근거 칩을 누르면 같은 패널 안에서 스크립트로 넘어간다. [[VA-UC-001#UC-H3]] 1번의 「위에서 아래 순서」와 다르다(8장).

**2. 홈 구성 — 결정: 사이드바 없이, 입력 카드 둘을 나란히 두고 아래에 목록.**
이유: 사용자가 하는 일이 「넣기」와 「다시 열기」 둘뿐이다. 넣는 방법 둘(YouTube 링크, inbox 파일)은 비중이 같아 나란히 둔다. 페이지가 넷이라 사이드바로 나눌 만큼 갈 곳이 없다.

**3. 첫 실행 — 결정: 설정으로 바로 보내지 않고, 홈에 배너를 띄우고 분석 버튼만 막는다.**
이유: 키가 없어도 이미 분석한 영상은 읽을 수 있다. 앱이 무엇을 하는지 먼저 보이고, 분석을 하려는 순간 설정으로 이어진다. 막힌 버튼도 누르면 UI-5로 가서 막다른 길이 없다.

**4. 사전 안내의 비용 — 결정: 합계와 줄별 금액(받아쓰기 / 요약·챕터·추천 질문)을 나눠 보인다.**
이유: 자막이 있어도 요약 비용은 든다. 비용 대부분은 받아쓰기라서, 어디서 돈이 드는지 보여야 취소할지 판단할 수 있다. [[VA-PRD-001#R8]]의 「비용 없음」과 다르다(8장).

**5. 받아쓰기 진행 — 결정: 조각 격자로 보인다.**
이유: 몇 분에서 십여 분 켜 두는 화면이라 멈추지 않았다는 것이 보여야 한다. 동시에 여러 조각을 보내므로 숫자 하나보다 칸이 실제 모습에 맞다. 실패했을 때 어디서 멈췄고 무엇이 보존됐는지가 한눈에 보인다.

**6. 진행 화면 — 결정: 결과 화면 안의 상태가 아니라 별도 페이지(UI-3).**
이유: 진행 중에는 보여 줄 결과가 없다. 한 페이지에 두면 「빈 칸투성이 결과 화면」이 된다. 주소가 따로 있어 목록에서 다시 열 수 있고, 끝나면 UI-4로 저절로 넘어가 흐름이 끊기지 않는다.

**7. 다이얼로그와 페이지 — 결정: UI-2·UI-6·UI-7은 다이얼로그, UI-5는 페이지.**
이유: 세 다이얼로그는 지금 화면 위에서 짧게 확인하고 닫는 일이고, 취소하면 원래 화면이 그대로 있어야 한다. 설정은 카드 넷으로 한 화면보다 길고, 첫 실행 배너에서 찾아가는 목적지라 주소가 있는 페이지로 둔다.

**8. 목록의 진행 중·실패 영상 — 결정: 분석을 시작하면 바로 목록에 올리고 상태를 보인다.**
이유: 진행 화면을 닫아도 분석은 계속된다. 돌아갈 입구가 목록 말고는 없다. 실패한 영상도 목록에서 열어 이어서 다시 시도할 수 있어야 한다.

**9. 결과 화면의 시각 — 결정: 스크립트 이동에만 쓰고, YouTube 시점 링크는 내보내기에만 둔다.**
이유: 보드가 그렇게 그렸다. 시각마다 링크를 걸면 누를 때 스크립트로 갈지 YouTube로 갈지 둘로 갈린다. **바뀜(2026-10-02)**: 플레이어를 열면 시각이 화면 안에서 그 장면부터 재생한다(32). YouTube 사이트로 가는 시점 링크는 그대로 내보내기에만 둔다.

**10. 핵심 인사이트 표시 — 결정: 이모지 카테고리 없이 두 자리 번호와 시각 칩.**
이유: 보드가 그렇게 그렸다. 인사이트는 출처 시각으로 찾아가는 것이 핵심이라, 번호와 시각이면 충분하다. [[VA-PRD-001]] 6절 미결을 닫는다(8장).

**11. 조각 숫자 — 결정: 진행 중 n은 완료한 조각 수, 실패 때 k는 실패한 조각 번호.**
이유: 보드 안에서도 두 뜻이 섞여 있었다('12 / 30'은 완료 수, '16 / 24에서 실패'는 조각 번호). 동시에 보내므로 실패한 조각 뒤의 조각이 이미 끝났을 수 있어, 완료 수는 따로 적어야 오해가 없다.

**12. 키 저장 버튼 둘 — 결정: [확인하고 저장]은 키만 곧바로 저장, 페이지 [저장]은 모델 선택만 저장.**
이유: 키는 확인이 통과해야 저장할 수 있고 결과를 그 자리에서 알려야 한다. 모델 선택은 확인할 것이 없으니 페이지 끝에서 한 번에 저장한다. 두 버튼이 같은 것을 저장하면 어느 쪽을 눌러야 하는지 헷갈린다.

**13. 진행 중인 영상 삭제 — 결정: 막지 않고, 작업을 멈춘 뒤 지운다.**
이유: 보드가 진행 중·실패 행에도 휴지통을 그렸고, 분석을 취소하는 버튼은 따로 없다. 잘못 넣은 영상을 멈출 방법이 삭제뿐이다.

**14. 내보내기 파일 위치 — 결정: 서버가 `data/export/`에 쓴다. 브라우저 다운로드는 두지 않는다.**
이유: 보드가 경로 `data/export/…md`를 보여 준다. 두 방식을 함께 두면 저장된 곳이 둘로 갈린다.

**16. 분석 중에 새 분석 — 결정: 대기열. 막지 않는다.**
이유: 사용자 결정(2026-09-21). 긴 받아쓰기가 도는 동안 다음 영상을 걸어 두고 자리를 뜰 수 있다. 동시에 돌리면 OpenAI 요청 제한과 비용 예측이 흐려져 하나씩 차례로 돈다. 대기 상태는 UI-1 행 · UI-2 안내 줄 · UI-3 대기 상태 세 곳에 보인다.

**17. 인터넷이 없어 키를 확인하지 못했을 때 — 결정: 배너 문구를 가르고 [키 넣으러 가기]를 뺀다. 버튼은 막지 않는다.**
이유: 사용자 결정(2026-09-21). 키가 틀린 것과 인터넷이 없는 것은 할 일이 다르다. 설정으로 보내도 고칠 것이 없다. 문구가 「분석 버튼을 누를 때 다시 확인합니다」이므로 버튼을 막으면 그 약속을 지킬 수 없다 — 누를 때 서버가 한 번 다시 확인한다(와이어프레임 1.4에서 드러난 것).

**18. 한눈에 보기 위치 — 결정: 「한 줄 요약」 바로 아래, 「핵심 인사이트」 위.**
이유: 결과를 열면 스크롤 없이 영상 구조가 보여야 한다([[VA-PRD-001]] 4장 한눈에 보기). 1440×900 창에서 막대가 첫 화면에 든다. 한 줄 요약은 한 문장이라 그 위에 두어도 막대를 밀어내지 않는다.

**19. 한눈에 보기 그리기 — 결정: 라이브러리 없이 HTML · CSS로 그린다. 노트에는 Mermaid.**
이유: 칸 · 점 · 노드를 누르면 스크립트로 가야 하고(4.4), 디자인 토큰과 요소 번호(`data-el`)를 그대로 지켜야 한다. 그림 라이브러리는 번들이 크고 누르기 · 토큰을 맞추기 어렵다([[VA-INFRA-001]] 3절).

**20. 마인드맵 — 결정: 뿌리는 한 줄 요약. 파트가 있는 영상은 요점을 뺀다.**
이유: [[VA-PRD-001#R11]]이 한 줄 요약 → 파트 → 챕터 → 요점을 정했다. 읽기 폭 760px에 파트 · 챕터 · 요점 세 단을 넣으면 요점 칸이 60px 안팎이라 읽을 수 없다. 긴 영상은 파트를 펴고 챕터까지 보이고, 요점은 아래 챕터 목록이 보인다. 노트의 Mermaid 마인드맵도 같다 — 처음에는 폭 제약이 없다고 보고 요점까지 넣었으나, 2시간 30분 영상(파트 5 · 챕터 27 · 요점 54)을 Mermaid 11로 노트 폭 700px에 그리면 노드가 겹쳐 읽히지 않았다(카드 D1). 사용자 결정(2026-09-30): 파트가 있으면 노트도 요점을 빼고 뿌리 → 파트 → 챕터로 그린다(UI-7). 파트가 없는 영상은 화면 · 노트 모두 요점까지다.

**21. 장면 칸 — 결정: 자르지 않고 줄여 넣는다(바탕 잉크).**
이유: 오래된 영상의 스토리보드 칸은 4:3(120×90)이다. 16:9 칸에 맞춰 자르면 발표자 머리 · 슬라이드 끝이 잘린다. 16:9 그림은 칸을 꽉 채우므로 차이가 없다.

**22. 인포그래픽 확인 — 결정: 누르면 UI-8로 한 번 묻는다.**
이유: 돈이 드는 동작은 UI-2처럼 시작 전에 값과 보낼 내용을 보여 준다([[VA-UC-001#UC-H9]] 2번 · 최소 보장). 한 장 약 $0.01이라도 무엇이 OpenAI로 가는지 알려야 한다([[VA-PRD-001#N3]]).

**23. 끌어 놓기 자리 — 결정: 「내 파일」 카드 안 맨 위, 놓기는 창 어디서나.**
이유: 끌어 놓기와 inbox는 같은 「로컬 파일 넣기」라 한 카드에 둔다. 칸이 작아도 창 전체가 받으므로 겨냥할 필요가 없다. 새 카드로 나누면 홈 입력 카드가 셋이 되어 「넣는 방법 둘」이 흐려진다(7장 2).

**24. 키가 없을 때의 올리기 — 결정: 올리기 전에 막는다.**
이유: 분석을 시작하려면 키가 있어야 한다. 수 GB를 다 올린 뒤에야 키 때문에 멈추면 기다린 시간이 헛된다. 분석 버튼과 같은 막힘 규칙(누르면 UI-5)을 따른다.

**25. 올린 사본 알리기 — 결정: 끌어 오는 중 덮개 · 사전 안내 · 설정 세 곳에 적는다.**
이유: 사용자의 관심은 「원본이 그대로인가, 사본이 남는가」다([[VA-UC-001#UC-H2]] 이해관계자). 놓기 직전(덮개), 비용을 결정할 때(UI-2 취소 안내), 나중에 찾아볼 때(UI-5 로컬 파일) 알린다. 사본이 지워지는 순간(분석이 끝남)은 따로 알리지 않는다 — 결과 화면이 열리는 것이 끝이다.

**26. 초점 고리 — 결정: 청록 2px를 2px 띄워서, 모든 요소에 같은 고리.**
이유: 청록은 이미 「지금 선택 · 위치」를 뜻해 「지금 여기」를 알리기에 맞고, 앱이 쓰는 모든 바탕(바탕 · 카드 · 옅은 면 · 위험 바탕 · 형광 바탕) 위에서 5:1을 넘는다(3.5). 띄워 그리면 청록으로 채운 칸 · 잉크 버튼 위에서도 고리가 따로 보인다. 사용자 승인 2026-10-01(세 번째 캔버스).

**27. hover — 결정: 한 단계 진하게, 새 색은 하나.**
이유: 보드에는 링크 글자색 hover만 있었다. 누를 것이 마우스 아래에서 반응해야 하지만 읽는 도구라 튀면 안 된다. 바탕을 한 단계 진하게만 하고, 값은 있던 톤을 돌려써 토큰을 늘리지 않는다(잉크 hover만 새로). 고른 것은 바꾸지 않아 hover와 헷갈리지 않는다.

**28. 한눈에 보기 키보드 — 결정: 줄마다 Tab 한 번, 줄 안은 화살표, 옮기기와 고르기를 나눈다.**
이유: 칸마다 Tab이 멈추면 2시간 30분 영상에서 42번(파트 5 · 점 10 · 챕터 27)을 지나야 마인드맵에 닿았다(와이어프레임 2장 미결). 화살표로 옮기기만 하고 Enter로 고르면 여러 칸을 지나도 스크립트가 뛰지 않는다. 좁은 칸은 이름이 보이지 않아 범례 자리에 이름 줄을 띄운다 — 마우스로 가리킬 때도 같다.

**29. 시각을 고른 뒤의 자리 — 결정: 이미 보이면 그대로, 아니면 가운데. 주소에 `?t=`.**
이유: 이미 패널에 보이는 구간까지 가운데로 다시 옮기면 읽던 줄이 눈앞에서 뛴다. 같은 시각을 다시 누르면 아예 움직이지 않아, 스크롤해 떠난 뒤에는 돌아갈 길이 없었다(카드 E5 뒤 진짜 스택 확인). 고른 시각을 주소에 남겨 새로 고침이나 설정에 다녀온 뒤에도 같은 곳을 본다 — 주소만 바꿔 써서 뒤로 가기가 시각마다 멈추지 않는다. 사용자 결정 2026-10-01.

**30. 탭을 오갈 때 대화 위치 — 결정: 읽던 자리를 지키고, 떠난 사이 새 답이 왔을 때만 끝으로.**
이유: 근거 칩을 눌러 스크립트로 갔다 돌아오면 읽던 답에서 이어 봐야 한다. 전에는 돌아올 때마다 끝으로 가서 긴 기록에서 자리를 잃었다(카드 E5 뒤 진짜 스택 확인). 떠난 사이 답이 오면 그 답이 끝에 있으니 끝으로 간다. 사용자 결정 2026-10-01.

**31. 짧은 알림 시간 — 결정: 4초, 마우스를 올린 동안 멈춤, 새 알림이 앞의 것을 바꾼다.**
이유: 쓰는 곳이 둘(이미 분석한 영상 · 내보내기 완료)이고 잇달아 뜨는 일이 사실상 없어 쌓을 까닭이 없다. 읽는 중에 사라지지 않게 마우스를 올린 동안은 멈춘다. 위치는 상태 보드 검토(8장 디자인 보강)에서 정한다. 사용자 결정 2026-10-01.

**32. 영상 같이 보기 — 결정: 오른쪽 패널 맨 위(스크립트 위), 처음은 재생 판.**
이유: 영상과 그 말을 한눈에 같이 본다 — 스크립트 바로 위라 시각을 누르면 글과 화면이 함께 움직인다. 왼쪽 첫 화면(한 줄 요약 · 한눈에 보기)은 그대로라 「스크롤 없이 구조가 보인다」([[VA-PRD-001]] 4장)를 지킨다. 스크립트가 짧아지는 대신 접을 수 있다. 제목 옆 작은 재생 판(후보 B)은 패널을 그대로 두지만 영상이 작다. 사용자 결정 2026-10-02(네 번째 캔버스 ①).

**33. 재생 판 — 결정: 이미 가진 첫 챕터 장면 위에 재생 버튼, 누를 때만 YouTube를 부른다.**
이유: 결과를 열 때마다 YouTube에 접속하지 않는다([[VA-PRD-001#N3]]). 그림은 장면 단계가 이미 만든 것이라 밖으로 요청이 없다. 음성 파일은 그림이 없어 72px 한 줄이다. 사용자 결정 2026-10-01.

**34. 올린 파일 · 따라가기 — 결정: 올린 파일은 재생하지 않고, 재생 위치를 따라 스크립트가 움직이지 않는다.**
이유: 올린 사본은 분석이 끝나면 지운다(디스크, 사용자 결정 2026-09-29). 따라가기는 사용자가 스크롤할 때 멈추는 규칙까지 들어 첫 버전에서 뺐다 — 시각을 누르면 그 시각부터 재생하는 것으로 충분하다. 사용자 결정 2026-10-01.

**35. 보낸 추천 질문 — 결정: 그대로 두고 체크 + '답 보기 →', 누르면 그 답으로.**
이유: 같은 질문을 또 보내면 비용이 다시 들고 기록이 겹친다. 빼면 「이런 걸 물어볼 수 있어요」가 비어 간다. '답 보기'는 누르면 무엇이 일어나는지를 글로 알린다(안 ①의 '물어봄'은 상태만 알린다). 작은 칩은 폭이 좁아 체크만. 사용자 결정 2026-10-01 · 2026-10-02(네 번째 캔버스 ②).

**36. 첫 캔버스에 없던 상태 — 결정: 지금 모양 그대로 확정, 짧은 알림은 창 아래 가운데.**
이유: 와이어프레임에 「캔버스에 없음」으로 그린 상태 열여덟과 두 번째 캔버스가 그리지 않은 것 일곱을 지금 코드의 모양으로 보드에 옮겨 보니 고칠 것이 없었다. 대기 상태도 정상 상태의 색을 그대로 쓴다 — 차례를 기다리는 것은 오류가 아니다. 사용자 결정 2026-10-02(네 번째 캔버스 ③).

**15. 대화상자 취소 — 결정: UI-6 [취소]는 연 화면으로 돌아간다.**
이유: 보드는 UI-1 위에 한 판만 그려 링크가 모두 UI-1이지만, UI-4에서 삭제를 취소했는데 홈으로 가면 읽던 곳을 잃는다.
