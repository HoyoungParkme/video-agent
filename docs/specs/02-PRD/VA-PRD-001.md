# PRD — 제품 요구

## 1. 목표

#### G1 영상 하나를 넣으면 요약·타임라인이 나온다
로컬 파일이든 URL이든 영상 하나를 주면 읽을 수 있는 요약과 시간별 타임라인을 돌려준다. 근거: [[VA-RFQ-001#Q3]]

#### G2 분석된 영상에 대해 대화할 수 있다
요약을 읽은 뒤 궁금한 것을 물으면 영상 내용에 근거해 답한다. 근거: [[VA-RFQ-001#Q4]]

#### G3 혼자 쓰는 도구로 끝까지 동작한다
개인 PC(GPU 없는 WSL2)에서 설치해 쓸 수 있고, 릴리스 AI의 핵심 흐름을 한 바퀴 재현한다. 근거: [[VA-RFQ-001#Q5]]

## 2. 비목표

| 비목표 | 이유 |
|---|---|
| 여러 사용자·계정·권한 | 사용자가 본인 한 명. [[VA-RFQ-001]] 4절 |
| 여러 영상 일괄 처리 | 첫 프로젝트는 영상 하나 흐름에 집중. 필요해지면 다음 버전 |
| 화면(장면) 이미지 분석 | 요약·Q&A는 음성(받아쓰기) 기반으로 만든다. 장면 인식은 GPU 없는 환경에서 비용이 크고, 릴리스 AI의 핵심 가치도 음성 기반이다. 장면을 **보여 주기만** 하는 것은 [[#R12]] — 요약·Q&A의 재료로 쓰지 않는다 |
| 로컬(오프라인) 받아쓰기 모드 | 받아쓰기·요약·Q&A는 OpenAI API로 한다([[#N3]]). GPU 없는 PC에서 로컬 모델은 1시간 영상에 수십 분~1시간 이상 걸려 [[#N1]] 목표를 못 맞춘다 |
| 블로그 글·퀴즈·플래시카드 | 릴리스 AI·NoteGPT가 제공하는 파생 산출물. 핵심 흐름이 아니다. 결과가 마크다운으로 나오므로([[#R10]]) 나중에 붙이기 쉽다. 마인드맵은 사용자가 결과를 써 본 뒤 [[#R11]]로 넣었다(2026-09-29) |
| 상위 댓글 요약, 번역 | Eightify·릴리스 AI 부가 기능. 첫 버전 제외 |
| 브라우저 확장(YouTube 페이지 안에 표시) | Eightify·Glasp 형태. 우리는 독립 도구 |
| 실시간 스트림·CCTV | RFQ에서 선택하지 않음 |
| 영상 편집·클립 생성 | 분석 도구이지 편집 도구가 아니다 |

## 3. 요구사항

### 3.1 기능

결과 화면은 시장 조사(릴리스 AI, Eightify, NoteGPT, Glasp, Recall, BibiGPT — 2026-09-15)에서 공통으로 나타난 요소로 이루어진다: **핵심 요약([[#R4]]) · 챕터 요약([[#R5]]) · 전체 스크립트([[#R3]]) · 추천 질문([[#R9]]) · 채팅([[#R6]])**. 어디에 어떻게 놓는지(두 열, 오른쪽 탭)는 화면 설계가 정한다. 모든 요약 문장은 출처 시각으로 스크립트에 연결된다(릴리스 AI의 "출처 추적").

사용자가 첫 배포를 써 본 뒤 「분석 내용이 가시성이 없다 — 다른 앱은 그림·그래프로 설명한다」고 했다(2026-09-29). 두 번째 조사(NotebookLM · Mapify · BibiGPT · 릴리스 AI · Eightify — 2026-09-29)에서 공통으로 나타난 그림 셋을 더한다: **한눈에 보기(타임라인·마인드맵, [[#R11]]) · 챕터 대표 장면([[#R12]]) · 인포그래픽([[#R13]])**. 앞의 둘은 이미 만든 결과로 그려 비용이 없고, 인포그래픽만 누를 때 이미지 모델을 부른다.

#### R1 로컬 영상 파일 입력

근거: [[VA-RFQ-001#Q1]]

사용자가 PC에 있는 영상 파일을 지정하면 분석 대상으로 등록된다. 로컬 파일은 세미나·강의 녹화본처럼 **시간 단위 길이**가 보통이다.

- [ ] mp4, mkv, mov, webm 파일을 받는다
- [ ] 영상 파일이 아니거나 열 수 없으면 이유를 알려 주고 멈춘다
- [ ] 음성만 있는 파일(mp3, m4a, wav)도 같은 흐름으로 받는다

#### R2 URL 영상 입력

근거: [[VA-RFQ-001#Q2]]

YouTube URL을 주면 영상(또는 음성)을 내려받아 [[#R1]]과 같은 흐름으로 분석한다.

- [ ] YouTube 동영상 URL(watch, youtu.be, shorts)을 받는다
- [ ] 제목·길이·채널명을 가져와 결과에 함께 보여 준다
- [ ] 내려받을 수 없는 URL(비공개, 삭제, 지역 제한)이면 이유를 알려 준다

#### R3 받아쓰기(스크립트)

근거: [[VA-RFQ-001#Q3]], [[VA-RFQ-001#Q4]]

영상의 음성을 텍스트로 바꾼다. 요약·챕터·Q&A의 공통 재료이며, 사용자에게도 그대로 보여 준다. 받아쓰기는 OpenAI 음성 인식 API로 한다([[#N3]]).

- [ ] 문장(또는 구간) 단위로 시작·끝 시각이 붙은 스크립트를 만든다
- [ ] 한국어·영어 음성을 처리한다. 언어는 자동 감지한다
- [ ] YouTube 영상에 자막(수동 또는 자동 생성)이 있으면 받아쓰기 대신 자막을 가져와 쓴다 — 받아쓰기 비용과 시간을 없앤다
- [ ] 스크립트를 화면에서 읽을 수 있고, 각 구간을 누르면 해당 시각을 알 수 있다
- [ ] 시간 단위 영상은 조각으로 나눠 받아쓰되, 사용자에게는 이어진 하나의 스크립트로 보인다

#### R4 핵심 요약

근거: [[VA-RFQ-001#Q3]]. 형태는 Eightify의 "8 key ideas"와 릴리스 AI의 "핵심 요약 + 출처 추적"을 합친 것.

영상을 안 본 사람이 30초 안에 "무슨 내용이고 볼 가치가 있나"를 판단할 수 있는 요약.

- [ ] **한 줄 요약**(TL;DR) 1문장 — 영상이 무엇에 대한 것인지
- [ ] **핵심 인사이트** 5~8개 — 각각 한두 문장. 영상 길이가 1시간을 넘으면 10개까지
- [ ] 인사이트마다 **출처 시각**(mm:ss 또는 h:mm:ss)이 붙고, 누르면 스크립트의 그 위치로 이동한다
- [ ] 요약은 영상 언어와 상관없이 한국어로 쓴다
- [ ] 스크립트에 없는 내용을 지어내지 않는다

#### R5 챕터 요약

근거: [[VA-RFQ-001#Q3]]. 형태는 릴리스 AI "타임라인 요약"과 BibiGPT "챕터".

영상을 주제 단위 챕터로 나누고, 챕터마다 시작 시각·제목·요약을 붙인다. 훑으면 영상 전체 흐름이 보이고, 누르면 그 부분으로 간다.

- [ ] 챕터는 시간 순서로 나열되고 시작 시각이 붙는다
- [ ] 챕터마다 제목 한 줄 + 요약 2~3줄(글머리)
- [ ] 챕터 수는 영상 길이에 비례한다 — 10분 영상 5개 안팎, 1시간 10~15개, 3시간 30개 안팎
- [ ] 영상이 1시간을 넘으면 챕터를 상위 **파트**로 묶어 접었다 펼 수 있다
- [ ] 챕터를 누르면 그 시각의 스크립트로 이동한다

#### R6 영상 Q&A

근거: [[VA-RFQ-001#Q4]]

분석이 끝난 영상에 대해 자연어로 질문하면 스크립트에 근거해 답한다.

- [ ] 답변에는 근거가 된 구간의 시각이 함께 붙고, 누르면 스크립트로 이동한다
- [ ] 영상에 없는 내용을 물으면 "영상에서 다루지 않는다"고 답한다
- [ ] 같은 영상 안에서 이어지는 질문은 앞 대화 맥락을 유지한다
- [ ] 질문·답변 기록은 영상별로 저장된다 ([[#R7]])

#### R7 분석 결과 저장·다시 보기

근거: [[VA-RFQ-001#Q4]] — Q&A는 분석 뒤 언제든 할 수 있어야 한다

분석 결과(스크립트·핵심 요약·챕터·Q&A 기록)를 로컬에 저장해 두고, 나중에 다시 열어 읽거나 질문할 수 있다.

- [ ] 분석한 영상 목록을 볼 수 있다 (제목·출처·길이·분석 날짜)
- [ ] 같은 파일·URL을 다시 넣으면 다시 분석하지 않고 저장된 결과를 연다
- [ ] 결과를 삭제할 수 있다

#### R8 진행 상태와 사전 안내

근거: [[VA-RFQ-001#Q5]] — 시간 단위 영상은 분석에 몇 분~십여 분이 걸리므로 멈춘 것처럼 보이면 안 되고, 시작 전에 얼마나 걸릴지 알아야 한다

- [ ] 분석 시작 전에 영상 길이를 확인하고, **예상 소요 시간과 예상 API 비용**을 보여 준 뒤 시작한다. 비용은 받아쓰기 몫과 요약·챕터·추천 질문 몫을 나눠 보인다 — 자막 있는 YouTube는 받아쓰기 몫이 0이고 요약 몫만 든다
- [ ] 현재 단계(다운로드 → 음성 추출 → 받아쓰기 → 핵심 요약 → 챕터 → 추천 질문 → 장면)와 진행률을 보여 준다. 출처에 필요한 단계만 보인다 — 자막 있는 YouTube는 자막 가져오기 → 핵심 요약 → 챕터 → 추천 질문 → 장면, 로컬 음성 파일은 음성 추출과 장면이 없다
- [ ] 장면 단계([[#R12]])는 맨 끝이고, 실패해도 분석은 끝난 것으로 본다 — 결과는 장면 없이 열린다
- [ ] 동시에 도는 분석은 하나다. 분석 중에 다른 영상을 넣으면 대기열에 들어가 앞 것이 끝나면 저절로 시작하고, 화면에 「대기 중」과 순서가 보인다
- [ ] 받아쓰기 단계는 조각 단위 진행(예: 12/30)과 남은 예상 시간을 보여 준다
- [ ] 중간에 실패하면 어느 단계에서 왜 실패했는지 보여 주고, 그 단계부터 다시 시도할 수 있다

#### R9 추천 질문

근거: [[VA-RFQ-001#Q4]]. 릴리스 AI의 "심층 질문 추천"에서 가져옴.

분석이 끝나면 이 영상에 대해 물어볼 만한 질문을 미리 제안해, Q&A([[#R6]])의 시작점을 준다.

- [ ] 분석 직후 추천 질문 3개를 보여 준다
- [ ] 추천 질문을 누르면 그대로 Q&A에 질문으로 들어가 답이 나온다
- [ ] 추천 질문은 스크립트로 답할 수 있는 것만 만든다

#### R10 마크다운 내보내기

근거: [[VA-RFQ-001#Q5]] — 혼자 쓰는 도구라 결과를 내 노트(옵시디언 등)로 옮길 수 있어야 한다. Glasp·NoteGPT의 노션/옵시디언 내보내기에서 가져옴.

- [ ] 핵심 요약·챕터 요약을 담은 노트와 스크립트를 마크다운 파일 둘로 저장하거나, 노트를 복사할 수 있다. 저장한 노트는 스크립트 파일을 `[[{제목} 스크립트]]`로 가리킨다 — 한 파일이면 2시간 30분 영상의 노트가 5천 줄이 넘는다(카드 C 실측, 사용자 결정 2026-09-29)
- [ ] 시각 표시는 `[12:40]` 형태로 남아 텍스트만으로도 위치를 알 수 있다
- [ ] YouTube 영상이면 시각이 해당 시점 링크(`?t=760`)로 걸린다

#### R11 한눈에 보기 — 타임라인 · 마인드맵

근거: [[VA-RFQ-001#Q3]] · 사용자 피드백(2026-09-29) · 두 번째 조사(NotebookLM 마인드맵 · Mapify · BibiGPT)

글을 읽기 전에 영상 전체 구조가 그림으로 보인다. 이미 만든 결과(한 줄 요약 · 인사이트 · 파트 · 챕터 · 요점)로만 그리므로 모델을 더 부르지 않는다.

- [ ] 영상 길이 막대 위에 파트 · 챕터 구간과 인사이트의 출처 시각이 보인다
- [ ] 한 줄 요약 → 파트 → 챕터 → 요점 순서로 뻗는 마인드맵이 보인다
- [ ] 막대의 구간 · 점과 마인드맵의 챕터를 누르면 스크립트의 그 시각으로 간다 — 인사이트 시각([[#R4]]) · 챕터([[#R5]])를 누를 때와 같다
- [ ] 내보낸 노트([[#R10]])에도 같은 그림이 들어간다 — 옵시디언이 그리는 Mermaid 코드로
- [ ] 이미 분석한 영상도 다시 분석하지 않고 보인다

#### R12 챕터 대표 장면

근거: 사용자 피드백(2026-09-29) · 두 번째 조사(BibiGPT · 릴리스 AI의 화면 캡처)

챕터마다 그 시작 부근의 영상 장면 한 장을 보여 준다. 장면은 보여 주기만 하고 요약 · Q&A의 재료로 쓰지 않는다(장면 분석은 비목표).

- [ ] 로컬 영상 파일은 원본에서 챕터 시작 시각의 프레임을 뽑는다
- [ ] YouTube 영상은 영상을 내려받지 않고 YouTube 재생 막대의 미리 보기 썸네일(스토리보드)에서 가져온다 — 크기는 영상마다 다르고(1080p 영상 320×180, 그보다 낮은 영상은 160×90 · 120×90 — 카드 D 실측) 약 10초 간격이라 시작 시각과 몇 초 어긋날 수 있다(사용자 결정 2026-09-29, 실측을 보고 다시 확인)
- [ ] 음성만 있는 파일이나 썸네일을 얻지 못한 영상은 장면 없이 보인다 — 그 때문에 분석이 실패하지 않는다
- [ ] 장면은 챕터 카드와 내보낸 노트([[#R10]])에 들어간다
- [ ] 이미 분석한 영상도 다시 분석하지 않고 장면을 붙일 수 있다
- [ ] OpenAI 비용이 들지 않는다

#### R13 인포그래픽

근거: 사용자 피드백(2026-09-29) · 두 번째 조사(NotebookLM 인포그래픽)

원할 때 영상 내용을 인포그래픽 한 장으로 그린다.

- [ ] 결과 화면의 버튼을 누를 때만 만든다 — 분석할 때 저절로 만들지 않는다
- [ ] 만들기 전에 예상 비용을 보인다. 기본은 OpenAI 이미지 모델 `gpt-image-2`의 낮은 품질(한 장 약 $0.006)이고, 설정에서 중간 품질(약 $0.05)로 올릴 수 있다(사용자 결정 2026-09-29 — 「좀 비싸다, 싼 걸로」)
- [ ] 재료는 한 줄 요약 · 인사이트 · 챕터 제목이다 — 스크립트 전체를 보내지 않는다
- [ ] 만든 그림은 결과 화면에서 보고, 내보낸 노트([[#R10]])에 들어간다. 다시 만들 수 있다
- [ ] 그림 속 글자 · 숫자는 틀릴 수 있다고 알린다 — 출처 시각이 없는 그림이라 요약 · 챕터를 대신하지 않는다

### 3.2 비기능

#### N1 GPU 없는 개인 PC에서 릴리스 AI 수준 속도

근거: [[VA-RFQ-001]] 4절 (WSL2, RAM 15GB, GPU 없음). 무거운 처리는 전부 API 서버가 하므로 이 PC의 성능은 병목이 아니다. 시간은 영상 길이에 비례하므로 **시간당** 목표로 잡는다.

- [ ] GPU 없이 설치·실행된다
- [ ] YouTube 자막이 있는 영상은 길이와 무관하게 **1분 이내** ([[#R3]])
- [ ] 받아쓰기가 필요한 영상은 **영상 1시간당 3분 이내** — 1시간 → 3분, 3시간 → 10분
- [ ] Q&A 답변은 10초 이내

#### N2 영상 길이 상한

로컬 파일은 시간 단위가 보통이므로 상한을 넉넉히 잡는다. (Recall은 5~10시간, BibiGPT 4시간 이상, 그 외 다수는 1~2시간.)

- [ ] 첫 버전은 **3시간**까지 지원한다. 넘으면 시작 전에 알려 준다
- [ ] 3시간 영상도 스크립트·챕터 화면이 버벅이지 않는다 (챕터 파트 묶음 [[#R5]])

#### N3 데이터 위치와 외부 API

받아쓰기·요약·챕터·추천 질문·Q&A·인포그래픽은 모두 **OpenAI API**로 한다. 사용자가 자기 API 키를 넣는다.

- [ ] 원본 영상·스크립트·결과는 내 PC에만 저장된다
- [ ] 외부로 나가는 것은 OpenAI에 음성 조각(받아쓰기용) · 스크립트 텍스트(요약·챕터·추천 질문용) · 질문과 앞선 대화와 관련 스크립트(Q&A용) · 한 줄 요약과 인사이트와 챕터 제목(인포그래픽을 누를 때, [[#R13]]) · 키 확인 요청, YouTube에 영상 ID(정보 · 자막 · 음성 · 미리 보기 썸네일)뿐이며, README와 설정 화면에 이 사실을 적는다
- [ ] API 키는 `.env` 파일 하나에 산다. 처음엔 사용자가 직접 적고, 설정 화면에서 넣으면 앱이 같은 파일의 그 줄을 고친다. 저장소에 커밋되지 않는다
- [ ] API 키가 없거나 잘못됐으면 분석 시작 전에 알려 준다

#### N4 설치 단순함

- [ ] 사용자 한 명이 README를 보고 30분 안에 설치·첫 실행까지 간다
