# USECASE (Cockburn)

## 0. 이 문서의 형식

Cockburn 유스케이스 템플릿을 따른다. 모든 유스케이스는 같은 12행 표 + 기본 흐름 + 확장으로 쓴다. 실패·대안은 전부 **확장**이며, `3a.`처럼 어느 단계에서 갈라지는지를 번호로 붙인다. 별도의 예외 절은 없다.

전체 17개. 사용자 목표 10개(추상 1 포함), 하위기능 7개. 그림 둘 — [[#UC-H9]] 인포그래픽 · [[#UC-S7]] 대표 장면 — 은 사용자가 첫 배포를 써 본 뒤 더했다([[VA-PRD-001#R11]] ~ [[VA-PRD-001#R13]], 2026-09-29). 같은 날 로컬 파일을 끌어 놓거나 파일 고르기 창으로 넣는 길을 [[#UC-H2]] 1번에 더했다([[VA-PRD-001#R1]]) — 새 유스케이스가 아니라 지정하는 방법이 하나 늘었을 뿐이다. 다섯 번째 배포 뒤 Google Drive에서 고르는 길을 같은 1번에 더했다([[VA-PRD-001#R15]], 2026-10-02).

**두 개의 축** — 목록은 액터로 묶고, 다이어그램은 패키지로 나눈다. 패키지는 사용자 행위 기준이다.

| 패키지 | 유스케이스 | 수 |
|---|---|---|
| 영상 넣기 | H0, H1, H2, H8, S1, S2, S3, S6 | 8 |
| 결과 읽기 | H3, H7, H9, S4, S7 | 5 |
| 질문하기 | H4 | 1 |
| 보관 | H5, H6, S5 | 3 |

**추상 유스케이스** — [[#UC-H0]] "영상을 분석한다"는 실제로 실행되지 않는다. [[#UC-H1]]·[[#UC-H2]]가 공통으로 가지는 "사전 안내 → 파이프라인 → 저장 → 결과 표시"를 묶은 것이며, 다이어그램에서 일반화 관계로만 나타난다.

**사용 형태**는 로컬 웹 UI([[VA-PRD-001]] 6절). 여기서는 "화면"이라고만 쓰고 어느 화면인지는 화면 설계가 정한다.

| OpenAI API | — | 보조 액터. 받아쓰기·요약·챕터·추천 질문·Q&A를 처리하고 인포그래픽을 그린다 ([[VA-PRD-001#N3]]) | HTTPS |

**시스템 경계**: 영상 분석 에이전트(화면 + 파이프라인 + 로컬 저장소)가 안쪽이다. YouTube, OpenAI, 사용자의 파일 시스템은 바깥이다.

**공통 이해관계자** — 개별 유스케이스에 반복해 적지 않는다.
- **사용자 본인** — 결과가 영상 내용과 어긋나지 않기를, 무엇이 외부로 나가는지 알기를 바란다 ([[VA-PRD-001#N3]])
- **API 비용을 내는 본인** — 예상치 못한 비용이 나가지 않기를 바란다 ([[VA-PRD-001#R8]])

#### UC-H0 영상을 분석한다 (추상)

| 항목 | 내용 |
|---|---|
| 범위 | 영상 분석 에이전트 |
| 수준 | 사용자 목표 (추상) |
| 주 액터 | 사용자 |
| 이해관계자와 관심사 | **사용자**: 영상 하나를 넣으면 요약·챕터·스크립트가 나오기를 바란다. |
| 사전조건 | OpenAI API 키가 설정되어 있다 ([[#UC-H8]]). |
| 최소 보장 | 실패해도 어느 단계에서 왜 실패했는지 남고, 이미 받아쓴 조각은 버려지지 않는다. |
| 성공 보장 | 결과(스크립트·핵심 요약·챕터·추천 질문, 영상이면 챕터 대표 장면)가 로컬에 저장되고 화면에 보인다. |
| 트리거 | 사용자가 영상을 지정하고 분석을 누른다. |
| 패키지 | 영상 넣기 |
| 포함(include) | [[#UC-S1]] (2번), [[#UC-S2]] (4번), [[#UC-S3]] (5번), [[#UC-S4]] (6번), [[#UC-S7]] (7번), [[#UC-S5]] (8번), [[#UC-S6]] (3~7번 내내) |
| 확장점(extension point) | `이미 분석한 영상` → [[#UC-H5]] |
| 일반화 | — (이 유스케이스가 [[#UC-H1]]·[[#UC-H2]]의 상위) |

**기본 흐름**
1. 사용자가 영상을 지정한다 (구체 방법은 H1·H2).
2. 시스템이 영상 정보와 길이를 확인하고 예상 소요 시간·API 비용을 보여 준다 ([[#UC-S1]]).
3. 사용자가 확인을 누른다.
4. 시스템이 자막 또는 음성을 확보한다 ([[#UC-S2]]).
5. 시스템이 받아쓰기한다 ([[#UC-S3]]). 자막을 확보한 경우 건너뛴다.
6. 시스템이 핵심 요약·챕터·추천 질문을 만든다 ([[#UC-S4]]).
7. 시스템이 챕터 대표 장면을 만든다 ([[#UC-S7]]). 음성만 있는 파일은 건너뛴다.
8. 시스템이 결과를 저장한다 ([[#UC-S5]]).
9. 시스템이 결과 화면을 연다 ([[#UC-H3]]).

**확장**
- **2a. 같은 영상이 이미 분석되어 있다**
  - 2a1. 시스템이 "이미 분석한 영상"임을 알리고 저장된 결과를 연다 ([[#UC-H5]]). 파이프라인은 돌지 않는다.
- **2b. 길이가 상한(3시간)을 넘는다**
  - 2b1. 시스템이 길이를 보여 주며 지원하지 않는다고 알리고 멈춘다 ([[VA-PRD-001#N2]]).
- **3a. 사용자가 취소한다**
  - 3a1. 아무것도 전송되지 않고 끝난다.
- **3b. 다른 영상이 분석 중이다**
  - 3b1. 시스템이 이 영상을 대기열에 넣고 "차례를 기다리는 중"과 앞 영상 수를 보여 준다. 앞 것이 끝나면 4번부터 저절로 이어진다. 동시에 도는 분석은 하나다([[VA-PRD-001#R8]]).
- **4a~6a. 어느 단계든 실패한다**
  - 4a1. 시스템이 단계·이유를 보여 주고, 그 단계부터 다시 시도할 수 있게 한다 ([[#UC-S6]]).
- **7a. 대표 장면을 얻지 못한다**
  - 7a1. 시스템이 장면 없이 8번으로 간다. 분석은 성공이다 ([[VA-PRD-001#R8]]).

#### UC-H2 로컬 파일로 영상을 분석한다

| 항목 | 내용 |
|---|---|
| 범위 | 영상 분석 에이전트 |
| 수준 | 사용자 목표 |
| 주 액터 | 사용자 |
| 이해관계자와 관심사 | **사용자**: 두세 시간짜리 녹화본도 끝까지 처리되고, 파일 자체는 밖으로 안 나가기를 바란다. 파일을 폴더에 옮겨 두지 않고 바로 넣고 싶고, 올린 사본이 디스크에 쌓이지 않기를 바란다. 강의는 Google Drive의 과목 · 장별 하위 폴더에 흩어져 있다 — 옮기거나 올리지 않고 그 자리에서 고르고 싶다. |
| 사전조건 | [[#UC-H0]]와 같다. 파일이 사용자 PC에 있다. |
| 최소 보장 | [[#UC-H0]]와 같다. 원본 파일은 수정되지 않는다. 올리다 멈추거나 분석을 시작하지 못하면 올린 사본이 남지 않는다. |
| 성공 보장 | [[#UC-H0]]와 같다. 결과에 파일명·길이·파일 지문이 함께 저장된다. 올린 사본은 분석이 끝나면 지워진다. |
| 트리거 | 사용자가 inbox 폴더 목록에서 파일을 고르고 분석을 누르거나, 화면에 파일을 끌어 놓거나 파일 고르기 창으로 고른다. Google Drive에서 폴더를 따라 들어가 고르고 분석을 누를 수도 있다. |
| 패키지 | 영상 넣기 |
| 포함(include) | [[#UC-H0]]의 포함 전부 |
| 확장점(extension point) | — |
| 일반화 | [[#UC-H0]] |

**기본 흐름**
1. 사용자가 영상 파일(mp4, mkv, mov, webm) 또는 음성 파일(mp3, m4a, wav)을 지정한다. 경로를 입력하는 길은 없고, 지정하는 길은 셋이다.
   - inbox 폴더 목록에서 고른다 — 시스템은 원본을 읽기만 한다
   - 화면에 끌어 놓거나 파일 고르기 창으로 고른다 — 시스템이 앱 폴더(`data/uploads`)로 올려 사본을 만든다. 올라가는 진행이 보이고 사용자가 멈출 수 있다 ([[VA-PRD-001#R1]], 사용자 요청 2026-09-29)
   - 연결한 Google Drive 폴더에서 하위 폴더를 따라 들어가 고른다 — 시스템은 원본을 읽기만 한다. 복사하지 않아 올리기를 기다리거나 화면을 지킬 필요가 없다 ([[VA-PRD-001#R15]], 사용자 결정 2026-10-02)
2. 시스템이 파일(올린 것이면 사본)을 열어 길이와 음성 트랙 유무를 확인하고 파일 지문을 만든다 ([[#UC-S1]]). Google Drive 파일은 지문을 크기와 앞뒤 일부로 만든다 — 끝까지 읽으면 Drive가 파일 전체를 클라우드에서 받아 1분이 넘는다.
3. 이후 [[#UC-H0]] 2~8번. [[#UC-S2]]에서 음성을 추출한다.
4. 올린 사본이면 분석이 끝난 뒤 시스템이 지운다 (사용자 결정 2026-09-29).

**확장**
- **1a. 영상·음성 파일이 아니거나 열 수 없다**
  - 1a1. 시스템이 "영상·음성 파일이 아닙니다"라고 알리고 멈춘다 ([[VA-PRD-001#R1]]). 끌어 놓은 파일은 올리기 전에 형식을 보고, 올린 뒤에야 열 수 없다고 알게 되면 사본을 지운다.
- **1b. 여러 파일을 한꺼번에 끌어 놓았다**
  - 1b1. 시스템이 한 번에 한 파일씩 올려 달라고 알리고 아무것도 올리지 않는다. 일괄 처리는 비목표다 ([[VA-PRD-001#R1]]).
- **1c. 올리다 멈췄다 — 사용자가 멈추거나, 떠나기를 골랐거나(1e), 연결이 끊겼다**
  - 1c1. 시스템이 올라간 부분을 지운다. 다시 끌어 놓으면 처음부터 올린다.
- **1d. 앱 폴더의 디스크가 모자라다**
  - 1d1. 시스템이 올리기 전에 알리고 멈춘다.
- **1e. 올리는 중에 새로 고침 · 창 닫기 · 앱 안의 다른 화면으로 가려 한다**
  - 1e1. 시스템이 먼저 묻는다 — 새로 고침 · 창 닫기는 브라우저의 확인 창, 앱 안의 링크는 앱이 띄우는 확인 창이다. 머무르면 올리기가 이어지고, 떠나면 1c다 ([[VA-PRD-001#R1]], 사용자 결정 2026-10-01).
  - 1e2. 앱 안에서 브라우저 뒤로 가기는 묻지 못한다 — 바로 1c다.
- **1f. Google Drive에 닿지 못한다 — Google Drive 앱이 꺼졌거나 로그인이 풀렸다**
  - 1f1. 시스템이 그렇게 알리고 다시 시도를 함께 보인다. 앱을 켠 뒤에도 그대로면 api를 다시 띄운다(README).
- **1g. 고른 폴더 · 파일이 그 사이 Drive에서 옮겨지거나 지워졌다**
  - 1g1. 폴더면 알리고 내 드라이브부터 다시 찾게 한다. 파일이면 등록이 찾지 못했다고 알린다.
- **2a. 음성 트랙이 없다**
  - 2a1. 시스템이 받아쓸 음성이 없다고 알리고 멈춘다. 올린 사본은 지운다.
- **2b. 이미 음성 파일이다**
  - 2b1. [[#UC-S2]]의 음성 추출 단계를 건너뛴다.
- **2c. 올린 파일이 3시간을 넘거나, 이미 있는 영상과 내용이 같다**
  - 2c1. 넘으면 시스템이 사본을 지우고 길이를 알리고 멈춘다([[#UC-H0]] 2b). 같으면 그 영상으로 간다([[#UC-H0]] 2a · [[#UC-S5]] 1b) — 그 영상에 작업이 있으면 사본을 지우고, 작업이 없으면(사전 안내에서 취소했던 영상) 사본을 그 영상의 원본으로 남긴다. 지우면 [분석 시작]이 읽을 원본이 없다.
- **3a. 사용자가 사전 안내에서 취소한다 ([[#UC-H0]] 3a)**
  - 3a1. 시스템이 올린 사본을 지운다. 아무것도 전송되지 않는다.
- **3b. Google Drive 원본을 처음 끝까지 읽는다**
  - 3b1. Drive가 클라우드에서 받는 동안 음성 추출이 길어진다(4.4 GB에 약 1분). 사전 안내의 예상 시간에 그 몫이 들어 있다.
- **4a. 분석이 실패로 멈췄다 ([[#UC-H0]] 4a~6a)**
  - 4a1. 시스템이 사본을 남긴다. 다시 시도하면 그 사본을 읽는다. 결과를 지우면 함께 지워진다 ([[#UC-H6]]).

**기본 흐름**
1. 시스템이 결과 화면을 연다. 왼쪽 본문에 영상 정보 · 한눈에 보기(영상 길이 막대 위의 파트·챕터 구간과 인사이트 시각, 한 줄 요약에서 파트·챕터·요점으로 뻗는 마인드맵) · 한 줄 요약 · 핵심 인사이트 · 추천 질문 · 챕터 요약(챕터마다 대표 장면), 오른쪽 고정 패널에 [스크립트] 탭과 [질문하기] 탭(기본은 스크립트). 인포그래픽을 만들어 두었으면 그 그림도, 아니면 만들기 버튼이 있다. 놓는 자리는 화면 설계가 정한다.
2. 사용자가 한눈에 보기로 전체 흐름을 보고, 한 줄 요약과 핵심 인사이트를 읽는다 ([[VA-PRD-001#R11]], [[VA-PRD-001#R4]]).
3. 사용자가 챕터 요약을 대표 장면과 함께 훑는다 ([[VA-PRD-001#R5]], [[VA-PRD-001#R12]]).
4. 사용자가 인사이트의 출처 시각, 챕터, 또는 한눈에 보기의 구간·점·마인드맵 챕터를 누른다 ([[VA-PRD-001#R11]]).
5. 시스템이 스크립트를 그 시각 위치로 이동시키고 해당 구간을 강조한다 ([[VA-PRD-001#R3]]).
6. 사용자가 스크립트 위의 재생 판을 누른다. 시스템이 고른 시각(없으면 처음)부터 영상을 재생한다 — YouTube 영상은 이때 처음 YouTube 플레이어를 불러온다 ([[VA-PRD-001#R14]]).
7. 플레이어가 열린 동안 사용자가 다른 시각을 누르면, 시스템이 스크립트를 옮기고 그 시각부터 재생한다.

**확장**
- **1a. 장면 단계가 생기기 전에 분석한 영상이다**
  - 1a1. 시스템이 결과를 먼저 보이고, 뒤에서 대표 장면을 만들어([[#UC-S7]]) 다 되면 챕터에 붙인다. 다시 분석하지 않고 OpenAI 비용도 없다 ([[VA-PRD-001#R12]]).
- **1b. 대표 장면이 없다(음성 파일 · 썸네일 없음 · 원본 파일 없음)**
  - 1b1. 챕터가 장면 없이 보인다.
- **3a. 영상이 1시간을 넘어 챕터가 파트로 묶여 있다**
  - 3a1. 사용자가 파트를 펼쳐 그 안의 챕터만 읽는다 ([[VA-PRD-001#R5]]).
- **4a. 스크립트에서 거꾸로 찾는다**
  - 4a1. 사용자가 스크립트 문장을 누르면 그 문장의 시각이 보인다.
- **6a. YouTube 영상이다**
  - 6a1. 재생 판을 누르기 전(또는 접은 채 시각을 누르기 전, 7a2)에는 YouTube로 아무것도 보내지 않는다. 그 시점으로 여는 YouTube 링크는 여전히 내보낸 마크다운([[#UC-H7]] 2a)에만 걸린다 — 사용자 결정(2026-09-21 · 2026-10-01).
- **6b. 끌어 놓아 올린 파일이다**
  - 6b1. 분석이 끝나 사본을 지웠으므로 재생하지 않는다. 플레이어 자리에 그 까닭을 한 줄로 알린다 ([[VA-PRD-001#R1]]).
- **6c. 원본을 재생할 수 없다(inbox에서 옮기거나 지움 · 브라우저가 재생하지 못하는 형식 · 앱 서버에 닿지 못함)**
  - 6c1. 시스템이 무엇이 왜 안 되는지 플레이어 자리에 알린다. 원본은 그대로다.
  - 6c2. 앱 서버에 닿지 못했으면 다시 시도를 함께 보인다(사용자 결정 2026-10-02, 카드 E7 코드 리뷰).
- **6d. YouTube가 재생하지 못한다(다른 사이트의 재생을 막음 · 지워지거나 비공개가 됨) 또는 YouTube에 연결하지 못한다**
  - 6d1. 재생하지 못하면 원본 영상 열기를, 연결하지 못했으면 다시 시도를 함께 보인다(카드 E7에서 찾음 — 지워짐 · 비공개).
- **6e. 음성 파일이다**
  - 6e1. 그림 없이 재생 막대 한 줄로 재생한다.
- **7a. 사용자가 플레이어를 접는다**
  - 7a1. 재생을 멈추고 스크립트 · 대화가 넓어진다. 펼치면 멈춘 자리에서 이어 본다. 접고 펼치는 것은 플레이어 아래 막대 전체다.
  - 7a2. 접힌 동안 시각을 누르면 시스템이 펼쳐서 그 시각부터 재생한다 — YouTube 영상은 아직 플레이어를 불러오지 않았으면 이때 불러온다(사용자 결정 2026-10-02 — 대화 칸이 좁아 접어 두고 쓴다).

2. 시스템이 영상 정보 → 한 줄 요약 → 핵심 인사이트 → 챕터 요약 순으로 노트를 만들고, 스크립트는 따로 마크다운으로 만든다. 시각은 `[12:40]` 형태로 남긴다. 노트에는 한눈에 보기 그림(옵시디언이 그리는 Mermaid 마인드맵·타임라인)이 들어간다 ([[VA-PRD-001#R11]]). 절 순서는 화면 설계와 MINISPEC이 정한다.

2. 시스템이 조각마다 시작 시각 오프셋을 기록한다.
3. 시스템이 조각마다 무음에서 다시 15초 이하로 잘게 나눠 OpenAI 음성 인식 API에 보내고 텍스트를 받는다. 잘게 나눈 경계가 그 구간의 시작·끝 시각이다 — 시각을 돌려주는 모델이 2027-02-26에 없어진다([[VA-PRD-001#R3]], 사용자 결정 2026-10-01). 언어는 API가 한국어·영어 중에서 감지한다. 조각이 끝날 때마다 진행(n/m)을 알린다 ([[#UC-S6]]).

  - 3a3. 사용자가 재시도하면 완료하지 않은 첫 조각부터 이어간다. 완료한 조각은 다시 보내지 않는다.
- **3b. 여러 조각을 동시에 보낼 수 있다**
  - 3b1. 시스템이 몇 개씩 병렬로 보내 시간당 3분 목표([[VA-PRD-001#N1]])를 맞춘다. 조각 안의 잘게 나눈 구간도 몇 개씩 동시에 보낸다. 순서는 4번에서 오프셋으로 복원된다.

#### UC-S4 핵심 요약·챕터·추천 질문을 만든다

| 항목 | 내용 |
|---|---|
| 범위 | 영상 분석 에이전트 |
| 수준 | 하위기능 |
| 주 액터 | 시스템 (호출자: [[#UC-H0]]) |
| 이해관계자와 관심사 | **사용자**: 요약이 스크립트에 없는 말을 지어내지 않고, 시각이 실제 발언 지점과 맞기를 바란다. |
| 사전조건 | 시각 붙은 스크립트가 있다. API 키가 유효하다. |
| 최소 보장 | 실패해도 스크립트는 남는다. |
| 성공 보장 | 한 줄 요약, 출처 시각 붙은 핵심 인사이트, 챕터 목록(1시간 넘으면 파트 묶음), 추천 질문 3개가 저장된다. |
| 트리거 | [[#UC-H0]] 6번. |
| 패키지 | 결과 읽기 |
| 포함(include) | [[#UC-S6]] (각 단계) |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 시스템이 스크립트를 시각 표시가 든 텍스트로 정리해 OpenAI에 보낸다.
2. 시스템이 한 줄 요약과 핵심 인사이트(5~8개, 1시간 넘으면 10개)를 만든다. 인사이트마다 출처 시각을 붙인다 ([[VA-PRD-001#R4]]).
3. 시스템이 챕터를 만든다 — 시작 시각·제목·글머리 2~3줄. 수는 길이에 비례한다 ([[VA-PRD-001#R5]]). 순서가 핵심 요약 → 챕터인 것은 화면의 단계 표시([[VA-PRD-001#R8]])와 같게 하기 위해서다.
4. 시스템이 추천 질문 3개를 만든다. 스크립트로 답할 수 있는 것만 ([[VA-PRD-001#R9]]).
5. 시스템이 인사이트·챕터의 시각이 스크립트 범위 안에 있는지 검사한다.
6. 시스템이 결과를 저장한다. 언어는 한국어.

**확장**
- **1a. 스크립트가 한 번에 보낼 크기를 넘는다 (시간 단위 영상)**
  - 1a1. 시스템이 시간 구간(첫 값 30분)으로 나눈다. 요약은 구간별 중간 요약을 먼저 만들고 그것을 재료로 한 줄 요약과 인사이트를 만든다.
  - 1a2. 챕터는 구간별로 만든 뒤 시각순으로 합친다.
- **2a. 영상이 1시간을 넘는다**
  - 2a1. 시스템이 챕터를 상위 파트로 묶는다.
- **5a. 시각이 스크립트 밖이거나 없다**
  - 5a1. 시스템이 그 항목을 다시 만들게 하거나, 가장 가까운 구간 시각으로 바꾼다.
- **1b~4b. API 호출이 실패한다**
  - 1b1. 시스템이 재시도하고, 실패하면 단계와 이유를 돌려준다. 스크립트는 보존된다.

| 항목 | 내용 |

| 수준 | 하위기능 |

| 사전조건 | 출처 식별자가 있다. |
| 최소 보장 | 저장 실패 시 기존 결과가 손상되지 않는다. |

| 트리거 | [[#UC-S1]] 4번(판정) 또는 [[#UC-H0]] 7번(저장). |

| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. (판정) 시스템이 출처 식별자로 저장소를 찾는다. 있으면 기존 결과를 돌려준다.
2. (저장) 시스템이 영상 정보·스크립트·핵심 요약·챕터·추천 질문을 식별자 아래 저장한다.
3. 시스템이 목록 항목(제목·출처·길이·상태 — 완료 날짜, 진행 중·대기 중·실패)을 갱신한다. 분석을 시작하는 순간부터 목록에 있고, 사전 안내에서 취소해 작업이 없는 영상은 목록에 없다.

**확장**
- **1a. 같은 YouTube 영상을 다른 URL 형식으로 넣었다 (watch vs youtu.be)**
  - 1a1. 식별자가 영상 ID이므로 같은 것으로 판정된다.
- **1b. 같은 파일을 다른 이름으로 넣었다**
  - 1b1. 식별자가 내용 해시이므로 같은 것으로 판정된다. inbox에서 고른 것과 끌어 놓아 올린 것도 내용이 같으면 같은 영상이다 ([[#UC-H2]] 2c).
- **2a. 디스크가 부족하거나 쓸 수 없다**
  - 2a1. 시스템이 이유를 돌려준다. 이미 만든 결과는 메모리에 남아 재시도할 수 있다.

**기본 흐름**

2. 받아쓰기 단계에서는 조각 진행(n/m)과, 지금까지 조각당 걸린 시간으로 계산한 남은 예상 시간을 함께 보여 준다.

**확장**

- **1b. 장면 단계가 실패했다**
  - 1b1. 실패로 표시하지 않고 분석을 끝낸다 — 결과는 장면 없이 열린다 ([[#UC-S7]]).

3. YouTube 영상이면 YouTube 재생 막대의 미리 보기 썸네일(스토리보드)을 받아 그 시각에 가장 가까운 칸을 잘라낸다. 영상은 내려받지 않는다 (사용자 결정 2026-09-29).

**확장**

  - 1a1. 장면을 만들지 않는다. 파이프라인에 장면 단계가 없다.
- **2a. inbox의 원본 파일이 없어졌다(옮김 · 지움)**
  - 2a1. 장면 없이 끝낸다.
- **3a. 미리 보기 썸네일이 없거나 받지 못했다**
  - 3a1. 장면 없이 끝낸다. 분석은 성공이다.
- **3b. 썸네일 간격 때문에 챕터 시작과 딱 맞는 칸이 없다**
  - 3b1. 가장 가까운 칸을 쓴다 — 몇 초 어긋날 수 있다 ([[VA-PRD-001#R12]]).
